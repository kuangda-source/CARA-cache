# CARA 实验执行流程：探索与确认

**R2，2026-10-25。** 目标是减少重复工程和过程文档，让每张卡产生可执行的科学决策。本次用户授权流程修改、新输入池增量审计和最小通用入口；没有新增GPU权限或预算。CAL66的原stage、α、强基线、66路径、8GPUh及检查安排保持不变。

冲突时遵守用户明确授权、AGENTS安全与证据规则、已登记卡的合同。本流程不追溯修改旧卡。科学口径见[探索/确认合同](../plans/cara_policy_generator_20261020/EXPLORATION_CONFIRMATION_CONTRACT_R1_20261025.md)及[CAL66合同](../plans/cara_policy_generator_20261020/CAL66_DESIGN_AND_DECISION_CONTRACT_R1_20261025.md)。

## 1. 卡片与证据

每张卡先写“回答什么；结果为X时做Y”，冻结输入、角色、seed、执行顺序、完整分母、费用与决策规则。[模板](../cards/TEMPLATE.yaml)保持简洁，详细矩阵和统计协议引用不可变文件及SHA，不把旧manifest另抄一份作为第二个真源。

| 项目 | EXPLORE | CONFIRM |
|---|---|---|
| 用途 | CAL/FIT筛查、机制与方案选择 | 冻结方法在未使用输入上确认 |
| 预算 | 完整报价和授权上限；8GPUh不是通用授权 | 完整报价和明确授权 |
| 科学口径 | 不要求全部候选过部署门；报告完整质量—时间比较 | 冻结主方法按预登记质量与预算条件验收 |
| 输入 | 已曝光CAL/FIT | 来源分组与增量曝光审计通过的新输入 |
| 验证 | 按变更范围复用或补验 | 同样按变更范围验证，加独立完整终态接受 |
| 文档 | 默认结束一页结果与决策 | 默认启动、结果各一页 |

探索性机制结果可以进入论文，但必须说明CAL/开发范围，不能冒充独立泛化证据。新DEV用于开发决策后不再充当最终确认；预留最终输入保持隔离。

## 2. 按变更验证，不重复造CPU卡

已接受组件在源码、配置接口、环境、模型资源及适用范围一致时复用原件。每张卡列出 `validation.changes` 与复用证据。

| 变更 | 最小必要验证 |
|---|---|
| 仅布局、角色、顺序 | 掩码/α/实际调用路径、角色别名、分母和完整报价；复用未变监督与评分 |
| guardrail、写出、编解码、评分 | 服务器GPU隐藏容器内验证受影响的真实路径、资源和失败边界 |
| 新模型、求解器网格、运行环境 | 对应真实生产入口与数值控制；不能以旧组件CPU通过替代 |
| 释放、计费、监督、存储 | 受影响生命周期、故障与独立终态组合检查 |

CPU验证可以并入同一流水线，不必为它另建实验卡、长文档或预约GPU。缩短配置不能绕过改变的路径；小权重fixture不证明真实模型资源可用，GPU隐藏CPU也不证明CUDA执行正确。确认卡不无条件重验全部未变组件。

两模式共同保留：实际UUID硬独占和唯一runner核验、设备锁、账本预约/单调时钟结算、输出容量与跨盘日志保护、真实入口验证、源码/配置/资源SHA、完整失败拒绝分母、不以DEV/部分结果调参、不碰他人任务、不泄露凭据。不得修改正在运行的stage。

## 3. 最小通用入口

第一版 `scripts/run_card.py` 是**规格与既有工具的薄封装**：校验规格/引用SHA，生成执行计划，调用白名单内已有的只读recover/capture与本地accept；不重写guardian、StorageGuard、计费或科学接受器。

- 默认离线validate/plan，无服务器连接。首个适配器只绑定现有CAL66句柄，作为已验组件的接线示例，不重新登记CAL66。
- 第一版不含prepare、launch、retry、自动评分重启、模式修改或预算预约功能。未来新卡需独立适配器、CPU证据和用户授权，不能因有YAML就启动。
- 相同卡与已有intent只恢复同一launch；UNKNOWN不盲重派。恢复连接使用已授权私有身份，不改全局SSH配置、不依赖长期master必然存活。
- 整体采集、释放结算和评分仍由原服务器监督器负责；GPU释放后再评分，CPU核数、内存、墙钟及vCPUh上限明确。
- 费用硬上限包含终止/释放余量，不能到上限后才开始停止。

只为下一张科学卡增加所需适配。通用化不能成为新输入审计或科学比较的前置工程项目。

## 4. 去重、重复与计时

去重比较完整执行身份：模型/权重、输入/预处理、seed、求解器/实际网格、D/C/A序列、α/β、读出实现、精度与相关运行设置。仅D掩码相同不够。指纹相同的**方法别名**可共享正式结果；计时重复、预热、数值控制和历史桥接保留物理槽位，不因同指纹删除。计划生成前完成去重，冻结后不缩卡。

每个正式请求都计完整时间。重复只在预登记子集进行，固定交错/反序，不把子集时钟赋给其他prompt。单seed首轮质量可以先评分；仅在重复latent和全部RGB一致时复用质量，不把确定性推广到未验证模型/环境。差异、拒绝、N/A和失败原样保留。

完整时间、核心时间、同输入新Native的比值与差值同时报告；“邻近”不允许借别的prompt或旧批次Native。先prompt内平均重复，再prompt等权：

`V = max(mean(T)/257.7712338712067, mean(T)/(0.8*mean(T_Native)))`。

**点估计可行**为V≤1；**稳健确认**还要求预登记prompt成对簇bootstrap的95%单侧上界≤1及其余质量/完整性条件通过。CAL66沿用其20000次、种子20261025、higher分位数合同；新确认卡自行预登记，不能无限重复到过线。原104/112失败保留，新探索不再受旧2秒预测门约束。

## 5. 监督、文档与提交节奏

服务器持续监督所有任务。短探索默认启动核验与结束收件；长任务保留一次技术半程，原卡既有检查不取消。异常或实测进度改变时复用原自动任务调整时间；无变化保持安静，不额外轮询。减少人工检查不等于减少服务器保护。

| 事件 | 记录与同步 |
|---|---|
| 启动 | 保存唯一回执、更新状态与导航；探索无需新增长研究记录 |
| 无意义变化 | 无新研究记录、不重新生成导航；机器监测原日志持续保存 |
| 失败/需行动 | 保存原件，简短说明影响、费用、修复范围；必要更新导航 |
| 完成 | 一页编号记录：问题、结果、证据边界、预登记决策、下一步；完整机器原件引用 |
| Git | 默认启动前代码/规格、结束后结果各一批；允许必要修复与重要状态同步，无硬性“两次”上限 |

一页规格/结果是可读性目标，不删除关键分母或证据。既有源码发布和精确SHA绑定规则保留。

## 6. 自主范围与复盘触发

已授权范围内的本地代码、测试、离线分析、GPU隐藏CPU验证与可逆技术修复继续推进。新输入元数据/曝光审计不等于新输入生成。用户在聊天中的明确授权有效，不要求再次在文档“签字”。

新GPU执行、重跑、科学范围/验收合同改变、增加预算需相应授权；已有明确批准不重复询问。未授权探索自主额度，本文件不补授。

同一问题连续两次失败或准备超过一个工作日：记录阻塞点、复用方案与下一最小步骤，触发复盘和必要上报；**不自动停止所有独立工作，不将普通修复变为审批门**。额外工程影响科学范围或费用时才提交具体变更供决定。

[问题队列](../plans/QUESTION_QUEUE.md)按决策价值/成本维护，每周简短复盘“解决了什么问题、改变了什么决策、实际GPUh/时间”。未知工时不编造。优先降低已曝光CAL上的重复投入，不靠增加实验卡或文档数表现进度。
