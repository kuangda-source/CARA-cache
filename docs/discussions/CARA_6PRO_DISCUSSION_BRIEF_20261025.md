**整理日期：2026-10-25，Asia/Shanghai。** 证据状态截至研究记录692及仓库提交`4c57d165`。本文是讨论材料，不是实验启动指令，也不是论文定稿。

## 0. 先读这一页：当前究竟到了哪里

我们研究基于Cosmos / WorldCache的视频扩散推理加速，核心有两部分：**用当前浅层信息修正缓存读出，以及用校准数据安排完整刷新的位置**。

目前最值得继续的正面证据是：

1. **固定布局下，修正A有局部及旧CAL端点收益。** BANK24六个新DEV上，单步局部误差平均下降约52.5%；旧CAL上，25D/24D的原phase A相对同布局C分别降低约9.7%/16.1%的LPIPS。
2. **数据导出的Shared26布局有明确的旧CAL收益。** 在当前Ada同路径比较中，Shared26-C相对S26-C的LPIPS下降16.26%，四个prompt同向，均时只多0.47秒。
3. **真实可行的24/25D工作点存在。** 两张完整验证卡都测到了预算内均值；卡住的是原先要求的计时预测尾部误差门，而不是所有缓存布局都必然超时。

目前没有成立的主张是：

- 原GRAPH自动搜索优于强简单布局；原P1没有选出预算内策略，后续同卡强基线又超过GRAPH。
- 修正＋数据生成布局在真正新输入上具有等实测时间的端点和独立质量优势。
- “年龄≤3”是普遍有效边界、CFG共享收缩本身带来贡献、1.5×以上有竞争力，或跨骨干泛化。

**当前路线已调整：** 暂缓新纯计时卡和原GRAPH102修复执行，改为“Shared24/25及一个20D探索档＋少步Native＋强基线”的CAL探索，然后冻结一个主工作点，进入新输入确认。

**当前只完成准备，没有启动新GPU：** Shared构造和生产请求入口已实现；新入口76条小张量CPU采样接受，30项本地检查通过；48组新输入池已完成限定范围曝光核查；CAL106完整报价预计9.97 GPUh、拟上限11.5 GPUh。完整监督/释放后评分/终态组合及独立质量模型资源CPU仍有待完成。

最新预算参考：累计上限226 GPUh，已用156.135454，旧两卡未知责任预约16.5，可用53.364546。新CAL106尚未预约。用户明确：**先不要启动GPU，原α、强基线和最终部署预算不变。**

## 1. 方法、名词和不变条件

### 1.1 D、C、A分别是什么

| 名称 | 含义 | 关键约束 |
|---|---|---|
| D | 完整模型计算，并产生真实锚点 | 作为后续缓存/修正的来源 |
| C | 直接使用WorldCache缓存读出 | 使用部署轨迹实际的历史窗口 |
| A | 当前浅层输出变化加到历史完整读出上 | β=1版本可写为`r̂_t = r_b + (p_t − p_b)`；A不写回真实D锚点 |
| phase A | 原有分阶段修正强度 | 目标更新步<25时α=1，≥25时α=.5 |
| nD | 一条实际36更新轨迹内的D数量 | 相同nD不自动等于相同实际时间 |
| 锚点年龄 | 当前步距离最近真实D的更新数 | 不是距离上一次A的步数 |
| Shared | 从已有Native轨迹变化能量导出的共享布局 | 当前实现是确定性的单次合法交换，不是学习式调度器 |
| GRAPH | 原P1用1624教师强制标签和动作价格搜索的策略 | 当前版本未显示强基线优势，已暂缓执行修复版 |

不是所有历史A实验都用phase A。Window24、CAL12的局部连续A对照以及BANK24单点使用过β=1、α=1；当前要保留的历史S26/25/24-A-phase是原阶段α。讨论时不能把这些身份混成一个方法。

### 1.2 实验环境及预算口径

- 主要骨干：Cosmos Predict2.5 2B；主要输出93帧、432×768，CFG双分支。
- 当前生产求解器请求35步实际执行36次更新；请求26/28/30实际为27/29/31次，报价和调用数按实际网格计。
- 历史部分CAL在A6000，近期验证在RTX 6000 Ada。跨硬件绝对LPIPS或时间不能直接相减归因。
- 完整请求时间包括方法安装、普通guarded生成流程、视频编码写出、清理。内部“core”包含条件处理、采样和解码，不是纯去噪kernel时间。
- 最终部署预算：`B = min(257.7712338712067秒, 0.8 × 同批新Native均时)`。257.771秒是绝对上限，不是每张卡都能用满的固定B。
- 实验费用上限和部署延迟上限是两种不同预算。GPUh还要计warm、加载、保存和实际持卡过程。
- 旧四CAL：AV28、Human199、Misc13398218、AV51，主要seed0，已经反复曝光。四个prompt是独立样本边界，重复和93帧不能扩充独立样本数。

### 2.7 CPU侧L1分析：幅度校准改善不等于放置改善

只使用完整1624，4折留一场景的探索性CAL分析：L1对C局部MSE的对数预测误差降低70.94%，但固定刷新名额的主诊断只改善0.35%，等C/A数量的局部动作分配改善2.00%。不同敏感性模型下分配收益不稳定。

**这里纠正此前讨论的一处遗漏：662已经完成了场景尺度收尾检验，并非一直没有分离。**

- 只用场景平均`log(d2)`：C预测对数MSE反而恶化0.52%；只用场景平均RMS分歧：改善0.68%，仅取得此前逐格L1改善量的0.96%。
- 原逐格L1总改善的代数分解：43.27%来自整体偏差平方项，56.73%来自场景内中心化残差项。即使使用留出标签选择最优单一尺度，也最多取得逐格改善量的48.21%。
- 因此“全部收益只是一个场景常数缩放”可以被当前检验排除；但场景内幅度信息不必改变同目标步下的源步排序，56.73%不能当作刷新决策增益，更不是因果份额。

按此前用户决定，这条浅层probe在线刷新门控线已经关闭，不自动恢复采集、L2/L3或学习式调度器。只保留“按请求预算”和“选择修正强度”两个有主线需求才讨论的休眠用途；本次Shared探索不重启它。

## 3. 当前问题：科学、测量与流程分别在哪里

| 类型 | 已确定的问题 | 不能直接下的结论 |
|---|---|---|
| 科学竞争力 | 原GRAPH被强布局超过；新输入端点证据缺失；当前主工作点约1.25× | 不能据此否定所有数据导出规则或缓存路线 |
| 机制解释 | 短区间A有收益，长连续复用出现严重退化 | 未独立证明年龄3是普适阈值或唯一主导变量 |
| 局部代理 | 当前教师代理最小值未对应最佳端点；实际历史窗口存在失配；L1幅度信息并非全由场景尺度解释 | 未证明所有局部代理均无效，也未量化失配因果损失或可靠刷新增益 |
| 测量 | 单步价格不能直接合成完整请求；环境和外层成本有漂移 | 小MARE不等于无偏；热降频不等于全部误差原因 |
| 评价 | LPIPS衡量贴近Native轨迹，独立质量可能方向不同 | 不能只用LPIPS判少步Native画质差 |
| 泛化 | 四旧CAL/seed0反复开发；第二骨干未有主结果 | CPU实现通过不等于科学泛化 |
| 流程 | 多次入口/依赖故障、计时修复消耗预算，迭代偏慢 | 不能取消独占、磁盘保护和费用原件来提速 |

最新输入池准备解决的是“没有可操作的新输入身份池”问题，不解决尚未运行新输入验证的问题。

## 4. Opus的主要反馈，以及我接受和修正的部分

### 4.1 先核对强基线，而不是只修预算

**Opus：** P1的SIMPLE可能远弱于历史间隔布局，4.92%优势不可信；应同硬件复现历史强基线。

**我的判断与结果：** 接受。104已证实该质疑重要：Shared26及S26-C/A均超过原GRAPH。当前优先检验Shared规则扩展，比继续修原GRAPH更有信息价值。

### 4.2 不再围绕“最大低估≤2秒”持续开纯计时卡

**Opus：** 该门主要受噪声影响，保留原失败，但取消它作为P1前置；用同块配对比值实测验收。

**我的判断：** 接受路线调整，撤回“必须先再跑一张完整计时验证才允许新科学探索”的优先级。但不同意由8对重复和高斯近似直接推出“基本不可能通过”或“5秒都由噪声解释”。新合同明确改未来门控，旧失败不改判。

### 4.3 科学比较与预算验收分开，画Pareto曲线

**Opus：** 同nD、同A数量比较质量，实测延迟作横轴，只在最终方法上确认0.8预算。

**我的判断：** 接受分层。固定D/A数量是有效结构对照，不自动等时间；C/A消融本来会改变A数量，Shared与S的限龄A次数也可能不同，须如实披露。最终确认必须包含完整请求时间，不能失败后换成core口径。

差值能抵消完全相同的加性变化，比值能抵消完全相同的乘性变化；二者都报告，但不能假定不同请求受到完全相同的扰动。正式点估计保持ratio-of-means，不悄悄换成mean-of-ratios。

### 4.4 确定性允许减少质量重复，计时只在子集重复

**Opus：** 第二轮相同seed不产生新质量信息，可降低费用；计时基本与prompt无关。

**我的判断：** 接受“先核对输出相等，再免重复评分”。不接受未经验证的prompt无关假设：112四prompt的全D两轮均时约296.98–300.50秒，S24-A约230.80–234.16秒；差异混有顺序/环境，既不能全归给prompt，也不能忽略。所有新输入首轮仍记录时间，预定子集追加重复；统计以prompt为单位。

### 4.5 少步Native前置；增加18–20D激进档

**Opus：** 少步Native是最便宜的决定性对照；激进配额可能放大差异，接近更有竞争力的速度档。

**我的判断：** 接受优先级，最终选定20D一档，避免18/19/20同时铺开。线性模型粗估18–20D约1.45–1.54×，仅是外推，不能预先写成速度结果。失真更大可能连方差一起增大，不保证少量prompt就足够。

少步Native在某工作点明确占优，支持停止该工作点，不直接证明所有模型/配额上的缓存研究无意义。没有显著差异也不等于已经证明等价。

### 4.6 探索与确认两种流程

**Opus：** 探索只保留commit/config/seed/hash，不必每次走完整验收和报价；确认再走严格协议。

**我的判断：** 接受分模式，但不取消完整范围、总费用上限、独占、磁盘保护、失败原件和结算。优先复用稳定生产组件，仅验证变更，并把相关问题合入一张有上限的卡。新探索不要求科学结果通过或每个候选预算可行，但仍要求原件可信。

### 4.7 输入池、费用、止损和论文定位

**Opus：** CPU先建30–50新prompt池；约3–5 GPUh的CAL卡后进入10–12 GPUh的新输入卡；失败则转分析稿。

**我的判断：** 对Opus“probe主要捕捉场景尺度”的概括应进一步修正：我之前只核对660而遗漏662，说成“尚未分离”；本次查到收尾证据后，改为“简单场景尺度解释未获支持，但刷新收益依然弱”。这不会重启已关闭研究线。

输入池已完成48组的范围内核查。费用必须按角色、warm、重复、控制和加载完整计算：当前保留全部强基线的CAL106预计9.97 GPUh，高于3–5h。六角色×16prompt首轮96条，再加4prompt×6角色重复24条，共120条；按0.065 GPUh/条约7.8h，仅为生成粗估，10–12h仍待正式报价。

止损应区分明确被支配、证据不确定、有意义正收益。分析稿同样需要机制证据，不能把几项失败直接提升为普适理论。第二骨干和更快工作点是后续竞争力问题，当前53.36h不能假定足够完成全部论文实验；本文不作会议录用或截稿可行性判断。

## 6. 我的当前判断，以及愿意被推翻的地方

**优先科学问题：简单、数据导出的放置规则，加上固定修正，是否能在新输入上得到可测的端点质量—时间优势？** 不是“能否把计时模型最坏误差压到2秒”，也不是“能否把原GRAPH救活”。

我认为值得继续的是Shared的可复现信号和固定布局A增量；当前最薄弱的是独立新输入、少步Native公平比较，以及完整方法的独立质量和跨预算证据。

我的方案也有明显代价，不能只替它辩护：

1. CAL106依然需要约10 GPUh，消耗约19%的53.36h可用余额；按11.5上限预约则约22%。它是否又过于全面，是本次最需要外部意见的问题。
2. 保留三条26D强基线能说明历史连续性，但它们已在104/112完整测过；是否应该少做部分重复角色、把预算转给新输入，值得讨论。任何调整应改成新的完整范围和报价，而非运行中删臂。
3. 单次交换保守且能回归历史，却可能限制Shared24/25/20的潜力；扩大为全局放置会增加新的算法自由度和验证需求，不能偷偷加进当前方法。
4. 限龄3缺乏单因素因果证据；当前用它做保守候选规则，并不意味着年龄诊断永远无需补。
5. 探索与确认分开有利于推进，但最终确认的统计验收不能再次变成一个小样本几乎无法判断的门。合同已经保留原预算点估计并要求置信区间；具体样本数、重复方案和有意义效应阈值需要在看新输入前明确。
6. 新输入方法若失败，首先判断是否明确被支配，还是样本不足；“转分析稿”是备选研究方向，不是自动得到一篇成熟论文。
