# 已有 P 轨迹的新发现：C 复用尚未被实际检验

2026-10-11。接续[323事前登记](323_WC_E4C_EXISTING_TRACE_CLOCK_COVERAGE_CPU_PREREGISTRATION_20261011.md)，完成既定 E4c 的已有轨迹 CPU 检查，没有新增 GPU 运行。

**最大的进展是明确了后续实验应区分什么：已捕获的全部 P 刷新之后，控制器均没有把 C 列入可行动作。因此，已有组合终点正结果不能直接归因于“P 来源延长了 C 复用寿命”；但这些轨迹也没有检验 C 读取 P 来源的实际质量。** 下一轮应比较控制器的代理判断与同状态真实误差，而非继续根据动作日志推断 P 来源寿命。

## 1. 实际覆盖和结果

完整状态清单保留原卡64位置和 E1 八位置，共72：22完整、1部分失败、49未开始。原卡失败、缺失和费用保持。22条完整路径中，20条含当前来源控制的36步历史，共720步；另两条 SOURCE_RA 不部署 P 来源，不补零为 P 轨迹。

| 已保存历史中的读出 | 全部捕获路径结果 |
|---|---:|
| P 刷新事件 | 89 |
| P 后下一步执行 P | 31 |
| P 后下一步执行 D | 58 |
| C 实际读取 P 工作源 | 0 |
| P 后下一步记录包含 C 可行候选 | 0 |
| 下一步决策理由为 `cheapest_feasible_bound_action` | 89 |

每个 P 事件的下一步就是 P 或 D，没有经过 C 后才替换来源的情况。按同一来源规则、场景、方法与 guided/final 输出身份标记数值重复后，有13个方法—输出组、51个 P 事件。**这些组不是13个独立场景**：实际仅 AV28 和 Human、seed0；原/CPU存储重复以及不同方法的相同输出不能增加泛化样本量。

代码中的候选集合先按代理可行性筛选，再按成本取最便宜动作。上述89次均进入正常可行性选择，因此 C 的缺席发生在候选筛选阶段，不能解释为 C 已可行但价格不划算。当前规则对 C-after-P 保留非零出生 floor、借用 D-only 漂移代理和区间累计量；这说明了筛选规则，**没有证明该规则过于保守，也没有测得真实 C-after-P 误差**。

“没有 C 读取 P 工作源”也不等于“P 没有使用缓存”：下一次 P 仍可能复用内部 MLP 投影缓存。这里区分工作源的深层复用与 P 执行器内部的投影复用。

## 2. 两种历史与观测缺口

本轮逐步保留行动前/后工作源 kind、birth、age，最后两个真 D 的步序和间隔，实际 α、分支状态、floor、区间代理、连续 P 次数与分层投影执行记录；第35步原生 cycle reset 保持。P 完成后 age=0 与下一步行动前 age=1 分开，P 不伪造真 D 锚点。

| 字段 | 已有记录能回答什么 | 仍缺什么 |
|---|---|---|
| 工作源年龄、真 D 历史 | 实际来源与两种时钟是否背离 | 该背离的真实误差后果 |
| α与分支状态 | 配置强度和实际读出分支 | 不把 α>0 自动当 A 已执行；P 分支不执行该 A 读出 |

| 投影更新记录 | 层、行数、fallback与缓存身份 | 各动作实现的真实逐步 wall |
| 路径取证 wall | 完整取证路径耗时 | 不能分解为真实动作/周期成本 |
| β、sigma | 不补造 | 缺逐步数值 β 与 sigma，缺 P 后 age1/2/4 配对 dense 诊断 |

## 4. 下一轮的区分假设

新增 **H-P-C-FEASIBILITY**：当前代理可能把一部分实际可接受的 C-after-P 排除；也可能其排除确实对应较大的实际误差。两者均保留，不能通过把 P floor 置零或直接放松阈值来预先选定解释。

下一张有限 E4c 卡应先冻结少量真实 P 事件和全部配对范围，再测 P 后 age1/2/4：

1. 从同一完整起点做匹配 P/D 来源，保留各自 latent、cache、solver 和 RNG；后续固定动作只用于离线归因，不能把另一臂状态写回来。
2. 在实际候选状态上比较 C 读出与该同状态 dense teacher，分别记录 guided 误差、代理可行性、数值 β/sigma、两种时钟及实际成本。Teacher 不更新部署锚点。
3. 对 A/P 组合保留匹配 A 无 P 对照；记录实际 A 是否执行，不能用 scheduled α 代替。P→P 投影复用另列。
4. 先报告代理与误差是否对齐，再决定是否需要来源条件的代理校准或执行器修订。所有不利点、fallback和费用保留；不新增训练或人工评审。

这登记了下一轮的问题与测量原则，**尚非已绑定事件、CPU验收和forecast的 GPU 卡**。E2/E3冻结方法、完整范围和执行顺序保持；E4c CPU检查没有替代其补验，也不把新解释写入正在等待执行的控制器。
