# F18 受影响生产 CPU 路径双端接受

2026-10-30。F18-C、F18-A1、Uniform18 已在四卡 Ada 和两卡 A6000 主机的 GPU 隐藏容器中，通过原 CLI、模型模块、双 CFG 和 UniPC 的小张量完整路径验证。每端两个 flow 模式合计36条成功路径、18次预定失败控制；两个原容器均正常退出。新增 GPUh、预约、评分和账本写入均为0。

## 实际范围

本轮验证两个原 CHECK 输入上的三种既定策略，覆盖六个逻辑位置。每个位置分别运行计时 ON、OFF 和审计 ON，共18条成功路径；每种角色另做文本拒绝、解码异常、写出异常，共九次失败控制。整个27位置 CPU 矩阵分别运行于两种原 flow 模式，每端总54次小张量尝试，不增加真实视频或独立科学样本。

运行复用已接受的 R2 CPU 工作者及同一真实模块/采样器测试夹具，只新增 F18 数值检查。权重、注意力、输入准备、解码和写出继续使用明确声明的 tiny CPU 替代；不加载 Cosmos 权重、不产生真实模型质量或速度结果。[启动前 CPU 意图](../plans/cara_next_stage_20261028/mainline/r2/F18_CPU_FRAGMENT_R1.json)从启动前保存的任务私有文件原字节归档，源文件 SHA 与两端实际 registration 相同。

两端都固定1 vCPU、4 GiB、无 swap、CPU26、无网络、只读根文件系统、DeviceRequests=null；GPU 可见性为空，CUDA 初始化、模型权重加载和下载均被原工作者禁止。工作600秒、退出60秒的原上限不变。

## 已验证的路径

- 每条成功路径均36次更新、36个 CFG pair、18次真实 D，实际动作序列与冻结 policy 完整一致，未发生未声明 fallback。
- F18-A1 仅在8、11、13、15、17、19做六次 A。step8 后两分支真实 D 历史仍为 `[6,7]`，step9仍为 C、来源D7；A 不更新真实锚点。
- 同输入同策略的计时 ON/OFF 与 clean/audit 三种运行，最终 latent、RGB、RNG 和完整语义历史逐值一致。
- clean 路径没有审计 guided copies、哈希或研究检查点；双时间满足原边界。审计路径保留全部36份 guided 输出。
- 三角色均通过拒绝、解码、写出失败的清理及禁止重放；缺少冻结或生产上下文均拒绝执行。

[双端接受回执](../reports/cara_fast_F18_affected_production_CPU_acceptance_r1_20261030.json)绑定两端完整 capture、原 CPU proof 和 registration 的字节 SHA、相同 CPU fragment 指纹及新源码。两端同时复用了22份当前仍相同的关键生产组件；原 B36 的52份执行、4份汇总、6份绘图源码及 A32 冻结保持。

本地接受器另通过六项控制，拒绝单端/重复主机、未结束或失败容器、原 proof 字节变化、缺少 flow/路径/锚点控制、不同片段，以及 CUDA 初始化或设备隔离缺失。接受器只能接受这份完整 CPU 桥接，不授予 GPU 执行。

## 仍未冻结与下一步

已补齐的是三条既定策略的受影响生产 CPU 片段。F18 整卡的预热、正式 Native、重复、必要控制、阶段中止条件、报价和派发/收尾组合尚未冻结；GPU 不就绪。该 CPU 矩阵不能直接作为 GPU 物理范围。

GPU 顺序继续保持 S 优先，实际方法冻结及风险复核后，再决定唯一相邻预算卡的完整范围和整卡费用。Q5 的50步网格仍需单独验证真实更新数、保护/年龄支持和生产适配，不把当前36更新组件直接升级为新网格接受。

R2 论文索引继续只登记原完整 B36 科学批次，本 CPU 不增加科学行。原匿名视频包的人类审阅仍另行接受；最终输入、额外 seed、旧失败与16.5 GPUh未知责任保持。
