# 原完整端点回执恢复的 CPU 组件

2026-10-30。预算搜索已具备完整RGB工件与持久化查询日志，但“生成和工件完成、查询返回尚未落盘时进程中断”会留下未知尾查询。本轮新增[原结果恢复入口](../src/wcomr/cara_budget_endpoint_recovery_r1.py)，只接收已完成的原同步CPU端点，不调用生成、不创建新查询、不重置查询额度。

## 恢复条件

入口重新核验原36更新/19D网格、FIT、卡摘要、控制器/日志/语法源码、Python版本、原查询身份和显式CPU评价来源。它持有原查询日志的排他锁；固定版本的CPU评价器在该锁内同步完成全部生成，所以活跃原回调无法同时被恢复。这个依据限定于当前同步CPU入口，不代替未来GPU守护进程、PID/start ticks、设备锁和费用释放验收。

只有最后一个缺失返回的原意图可补写。先读取两份Native教师和两份候选的完整请求证明、身份、93帧RGB编码、尺寸与SHA，再计算完整双FIT MSE。缺一份、字节损坏、错教师/上下文/源码、实际D数改变或原回调错误，都保留原状态并拒绝写入。完成的旧回执只读返回，已有错误及损坏回执不覆盖。

补写沿用原日志的独占创建与fsync，回执中附恢复器源码SHA及四份原工件摘要。写入失败仍保留未知；再次操作只能重新核验原完整工件后补写返回，没有生成重试路径。回执不含GPU准入或物理GPU终态已验证声明。
