# H1 机制诊断后的判断与下一步 CPU 准备

2026-10-03。依据 [H1 中间点](79_WC_H1_LOCAL_LIFETIME_R1_CARD_AND_RESULTS.md) 与 [早晚双 CAL 完整结果](80_WC_H1_GENERALIZATION_R1_CARD_AND_CPU.md)。这是下一阶段的 CPU 准备范围，未选定或提交新 GPU 卡，不增加累计 12 GPUh。

## 当前能判断什么

两个曝光 CAL 的四个窗口中，dense-held 预测的 velocity 相对当前同状态完整计算偏差为 7.25%–40.27%；D/MF/S 的双字段 5% 描述性筛查均为 0/24。该线不是视频质量门，不能据此否定原 WorldCache 的视频质量，也不能从三个离散 K 推出连续安全寿命。

稀疏来源并非处处安全：human 早期 residual 误差达 7.30%–7.58%，而 velocity 误差为 1.55%–1.73%。当前整组 D/S 热耗时比为 1.056–1.143×，有局部成本信号，但没有候选视频或端到端收益。

配对分解表明，未来 S−D velocity 扰动为当前真值能量的 0.54%–2.16%，绝对扰动相对来源为 0.339–1.827 倍。common 晚期较明显放大，human 晚期第 4 步反而收缩；交叉项可正可负。总误差稍降可来自抵消，不能称稀疏增强质量。来源、场景与阶段有差异，但两 CAL/相关 CFG/四个来源窗口不足以给出普适来源规则、单调寿命或统计交互。

因此，保留 WorldCache 主线，暂缓复杂 H2 分组、来源学习路由和 Trust Head；不继续机械追加相似局部诊断。下一科学缺口是：**简单 S/D 刷新组合在真实闭环中能否保持结果，并兑现净耗时收益。** 沿用长程计划的简单方案优先原则；RV 的同状态、同后缀、同预算收益标签仍未具备，不用本轮局部误差冒充。

## 下一 CPU 范围

1. 在独立核心中跑完官方实际 36 个 solver 更新/72 CFG，而不是以 PrefixComplete 在第 33 步退出。使用同一 shared preparation、完整 RNG、求解器、模型模式与请求绑定；证明原 D 路径和带记录的 D 路径的全部九门、完整最终 latent 与输出接口一致。禁止 CUDA、权重加载和真实模型前向；stand-in 的解码/写出只证明接口。
2. 从现有 13/21/33 检查点做进程内恢复并继续到最终步，保持后缀/时间网格不变。逐项核对 UniPC 多步历史、各 CFG 缓存、计数、条件、生成器、显式 buffers 和最终返回；区分生产函数检查、实际官方 prepare/UniPC CPU 检查与未来 GPU 整管线续推。不给已有指纹追认独立可重启分叉能力。
3. 简单候选保留官方 probe、判据、强制 dense 边界和层 6/23/27 fallback；只在允许的真实刷新位置使用既有 sparse deep self-attention，QKV/RoPE/MLP/cross 与现有阈值保持。任何 S/MF 产物明确属于 approximate reference，不能成为 true-dense 历史或在线校准真值。先确认原生 WC 的 residual window、probe window、flow/warp 和刷新状态能表达这一语义，再接候选。
4. D/S 共享同一包装层、条件和输入，不在线读取当前 dense teacher、最终视频或本轮误差选动作。CPU 覆盖跨请求/CFG隔离、暖启动/强制刷新、缓存命中、历史不足、非 finite、条件变化和清理。对部署行为变化做真分支控制，不把复刻实现的断言当质量验证。

先完成第 1–2 项并按结果收窄第 3 项。若完整恢复或 approximate reference 语义不能保持，先定位具体组件，不启动闭环 GPU。CPU 结果和新实现各自记录 source；封存本轮 `7711126` 与全部失败历史。

九门严格等价只验收 D/D 无扰动控制。D/S 闭环会改变后续 latent，也可能改变官方判据给出的刷新 trace；不要求它与 D 的哈希相同，必须记录真实轨迹与成本。如果增加 baseline trace 的固定位置回放，只列为机制对照，不能作为在线可部署策略，也不能用 shadow 诊断代替实际闭环。

## 下一 GPU 卡需要重新具体化的内容

下一卡至少包含干净官方 WC 对照与简单 WC+S；是否加入 Native、S-only 和重复计时，按真实匹配资产、完整成本与当前余额决定，不能删掉已冻结卡中的对照。两个当前场景继续只作开发诊断，不称独立确认。此前 Native 视频只有在版本、模式、输入、seed、网格与输出规格全部匹配后才可复用。

先用既有完整生成/解码成本和本轮实测做具体包络，包含加载、首次内核、调度、参考维护、解码、写出和失败；先定义干净时间口径、重复/顺序及质量对照，再冻结 card/source/payload。完整当前源的 CPU/source/assets/import 检查、现场 VRAM/compute/锁/无 inflight/余额全部通过才准入，不复用已消耗的 r4、H0、H1 单次窗口。

运行后先做全视频自动保真、运动与时序检查及输出原件审计；现成代理只能支持其覆盖的结论。无完整视频或净时间优势则仍为机制诊断，不推进来源路由复杂化。独立 DEV/第二 seed、调优 WC 与少步 Native 的公平曲线仍是后续方法接受条件。非必要不新增人评、付费评分、训练或外部资源。
