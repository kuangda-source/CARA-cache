- RA＋阶段A：已经有完整开发集终点正信号，立即进入候选冻结、新提示词确认和干净计时。
- P：部分MLP更新已真实执行，继续做来源/选择闭环和执行器成本改进；四层50%版本只是当前实施点，不是整个稀疏缓存方向。

## 3. 新发现一：相对RA，当前更像“廉价质量增强”，未必直接更快

报告成本是两个probe已支付后的动作增量，必须与CFG分支计数分开：

| 双分支动作 | 秒 |
|---|---:|
| C | 0.16846 |
| A-W1 | 0.33763 |
| A-β1 | 0.33811 |
| P | 6.17331 |
| D（普通） | 6.24938 |
| D（维护P状态） | 6.25420 |

以下仅是常数费用模型，不是实测预测或新测速：
假设RA只使用CC/DD，阶段候选只使用A/DD；每视频36更新、四视频144更新。
RA：56个DD＋88个C；
阶段W1：57个DD＋87个A；
阶段β1：55个DD＋89个A。

于是动作成本总和：
- RA：364.78976秒；
- 阶段W1：385.58847秒；
- 阶段β1：373.80769秒。

相对RA，模型上分别多20.79871/9.01793秒，即每视频约5.20/2.25秒。
未计probe、条件处理、解码、不同状态成本、控制器和内存行为，不可报告为实际减速。
若trace里存在混合动作、非A回退或保护行为，应按真实trace重算，而不是强套计数。

含义：对WC少deep调用，不等于对RA也更快；RA已经承担了很大部分调用减少。
真正机会是把质量余量用于更激进、经验证的工作点，在同质量下进一步省时。
应画RA和候选各自少量校准工作点的真实LPIPS—时间前沿，而非只要求当前单点同时在两轴获胜。

## 4. 新发现二：阶段减弱修正的贡献，可能强于“估计β”本身

β=1与拟合W1都在阶段减弱后改善，说明最值得保留的共同因素可能是：
联合目标、利用当前浅层、控制修正幅度，以及它们与后续选择的闭环交互。
尚不能判定拟合β无用。

一个用于后续诊断的参数化（需确认是否与当前实现等价）：
令最终guided基线预测为v0，修正提案为v1，d=v1-v0，
v(α)=v0+αd，e=v0-v*。则
L(α)=||e||²+2α<e,d>+α²||d||²，
α*=-<e,d>/||d||²（非零分母，可再约束范围）。
α*只能用离线teacher分析，不能作为线上真值。

这说明后期强度0.5有效，可能是对提案幅度/方向不确定性的抑制，
不证明“后期不重要”或“越弱越好”。
后续若需要算法深化，优先考虑极少参数的强度校准、实际sigma/step-size条件，
而非立即训练大Head。第25步不能无条件跨solver/步数迁移。

可选的低成本工程检查：
在α=1的阶段，基线head是否仍有在线消费者？
若没有，可能只需执行候选head；若有，保留。先做依赖分析与等价测试。
不能把两个非线性head输出的混合，直接移到head前并宣称等价。

## 5. 新发现三：P的经济性必须按“替代谁”计算

当前P每次相对维护状态的D仅节省：
6.25420−6.17331=0.08089秒。
4/5/6/7次一对一替代的直接节省仅0.324/0.404/0.485/0.566秒。
这很难从已有27.71秒控制路径差异中识别，不能用现有固定顺序pipeline计时证明这种收益。

若P原本的位置会执行C，当前增量：
6.17331−0.16846=6.00485秒。
后续将一次D改为C节省：
6.25420−0.16846=6.08574秒。
忽略其他开销，至少需要约0.9867次未来DD被C替代，才能回本。
即一个P几乎必须替代一个未来完整双分支刷新，而不只是减少一次CFG单分支。

因此：
1. P替代当前D：直接收益很小，重点看覆盖、源寿命和质量。
2. P插入当前C/A：必须显著改变未来D需求或带来可量化质量优势。
3. P使更多C/A变得可用：属于真正的闭环协同，应比较总成本。
4. 若P只是一种与D近价的“温和更新”，必须与相同插入时机的D比较，证明其非价格价值。

建议检查64卡中的“dense对照”具体是什么。
若不是“在候选P的相同位置用D，并保留相同其余动作掩码”，需补一个小规模对照。
受控掩码对照用于归因，不是可部署策略。
另做同一冻结控制规则下P→D的自适应对照，可测总后续效果；两者不要混为一谈。

## 6. 新发现四：P高精度不等于少算很多——当前覆盖非常保守

旧报告定义为28层、2层probe、26层deep；新P只在4个deep层减少50% MLP行，attention仍全算。
若各层MLP成本接近，理想少算的MLP量只相当于2/26≈7.69%的deep MLP，
还不是整个deep组的7.69%，且未减去gather/scatter、投影、缓存维护。
所以1.29%的整组省时并不反常。

相对C降低90%–95%的局部误差，说明当前近全算的P有较高精度；
不能据此推断误差集中在那四层、少量更新足以恢复整体或选择器很聪明。

积极推进方式：
固定50%活跃率和选择规则，按实测MLP时间与新增状态显存比较4→8→12层。
不同时搜索密度、层集、来源规则和阈值。通过真实D预填新增层所需缓存，不伪造历史。
超过显存预算则降低组数或改状态布局，不直接关闭保护。
真实省时达到可识别水平后，才再加入attention边稀疏；P与此前SpargeAttn必须分开命名。

## 7. 新发现五：P的“工作缓存年龄”和W1的“可信历史年龄”可能背离

报告已经正确区分D可信锚点与P工作来源；P创建误差非零，未来漂移先验暂借D（TRANSFER）。
潜在反馈：
P替代D -> dense anchors更新变少 -> 拟合W1使用的真实历史更陈旧 ->
A误差/风险校准变化 -> 改变后续P/D选择。

这不是已观察到的失败机制，只是可检验的联合假设。
最小新增trace应区分：
- 工作来源birth age；
- 最近两个D的更新时间、sigma间隔；
- 每层被复用部分的年龄概况（若已有，不重复建设）；
- W1是否有效、β与回退、A/P/D动作；
- P后首次D的时间及期间累计成本。

β=1不拟合历史增量系数，可能与拟合W1在P轨迹上有不同稳健性；
目前不应预先断言哪一个更好。

对P源的先验先补少量真实P后age 1/2/4的诊断，
用同一实际状态的dense只作离线评价，不更新本次决策。
来源误差与后续漂移可能相关；经验floor+drift不是自动成立的独立可加终点模型。
若floor过高，P被保守地频繁替换；过低则高估寿命。两方向都要保留。

## 8. 技术停止：正确的恢复与利用结果方式

报告：14条视频/最终张量已写出，但未通过该卡全量审计；第一规则AV28八方法齐，Human六方法。
原卡整体状态仍FAILED_TECH，费用1.507741GPUh照计。

建议以新登记的CPU任务逐路径检查并评分：
配对reference、配置/输入hash、36更新/72调用、最终tensor、视频93帧、来源事件与动作合同。
审计通过路径标为PATH_VALIDATED；缺失标明，不补零、不换样。
AV28完整方法组可做局部开发比较；Human只做确实齐全的对照。
由于顺序停止与内存问题，缺失可能与方法/场景相关，不能对14条平均后声称完整方法泛化。

检查点诊断与线上方法状态分开：
- 方法必需：D历史、P工作源、solver、RNG、CFG控制状态；
- 研究额外：为了反事实、取证和恢复重复持有的深拷贝/观察张量。
修复应保留前者与恢复语义，减少后者的驻留或重复复制，而非删除安全检查。

PyTorch官方资料支持区分tensor allocated、allocator reserved和device free，
以及用短窗口memory snapshot定位分配；部分外部CUDA分配不在PyTorch snapshot中。
empty_cache仅释放未使用的缓存块，不会释放仍被引用的活跃张量，不能作为通用修复。

需要的两种验证：
失败Human方法冷启动能否通过原失败点并完成；
在前序路径运行后，同方法是否还出现递增的活跃内存。
前者失败倾向单路径容量问题，后者失败提示跨路径生命周期问题；两者都只是诊断分类。

修复纯属状态布局/生命周期且等价检查通过时，可申请复用合法旧路径，仅补缺失部分；
不是静默缩卡或改写旧失败。若修改算法、精度、source semantics，则另开方法版本，不能无验证混表。

## 9. 推进顺序

立即：按许可做CPU逐路径审计/评分；登记失败点最小内存修复。
并行研发：冻结阶段W1/β1，先新提示词确认；不依赖P完成。
修复通过：保留原64科学范围，用新manifest续跑/补齐；及时逐路径评分。
P有界深化：成本覆盖扫描＋相同P时机D对照＋少量来源寿命诊断。
最后：对幸存整体方法画真实质量—时间前沿，补最小机制消融及确认。

这不是拆成互不相干项目：三线共享同一设置、数据与控制器；
只是不要让一个尚未成熟的执行器成为已经有信号的方法的发布前提。
