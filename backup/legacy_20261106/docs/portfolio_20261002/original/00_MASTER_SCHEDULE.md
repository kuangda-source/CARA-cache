# 视频世界模型质量—效率研究：总调度与方向决策

**日期：2026-10-02｜版本：v1.0｜类型：研究计划，不是实验报告**  
**适用范围：WorldCache 优化、OMR 优化、专家化蒸馏。**  
**执行边界：不新增 GPU/费用授权，不启动任务，不自动中止、重启或覆盖其他项目。**

## 0. 总决策

采用 **两条应用主线 + 一个可升级的方法候选**，但实行 **一个主要 GPU 执行槽**。

- **A / WorldCache：** 尽量少计算，同时保持原生生成的保真与时序质量。先改进近似，再按证据选择刷新调度或可学习残差补偿。
- **B / OMR：** 保留真实有效的纠正能力，减少纠正成本，或者在相同时间内提高语义—物理表现。先复现教师，再做无训练简化。
- **E / 专家化蒸馏：** 验证昂贵映射是否可由廉价学生逼近、不同状态是否需要不同专家，以及路由是否值得成本。拥有单独实验计划，但暂不占第三个长期 GPU 执行槽。

E 可以并入 A 或 B，也保留独立发展的机会。**单个预测头不等于 MoE；多个专家不自动等于功能解耦；三条线不要求合成一篇论文。**

默认当前入口是 **接续 WorldCache 已有实验的第一个未解决问题**，不是无条件从 W1 第一项重新跑。只有读取本地最新结果，才能知道这一入口实际是复现、近似诊断、闭环确认还是后续分支。

## 3. 统一愿景与三个不同的优化目标

### A：保持原生结果的低成本生成

\[
\min_{\pi,A}D\big(V(\pi,A),V_{\mathrm{native}}\big)
\quad\text{s.t.}\quad T(\pi,A)\le B.
\]

\(A\) 是缓存近似器，\(\pi\) 是刷新策略。W1/W2 首先改 \(A\)，W3 首先改 \(\pi\)。它们耦合，但应先隔离变量验证。

### B：以更低成本获得有效纠正

\[
\max_{\pi_c,C}Q_{\mathrm{task}}\big(V(\pi_c,C)\big)
\quad\text{s.t.}\quad T(\pi_c,C)\le B.
\]

\(C\) 是纠正算子，\(\pi_c\) 是调用安排。这里的质量目标不是“越接近原生越好”；纠正原生错误可能必须离开原生视频。JEPA 能量是方法信号，不自动等于物理正确性。[R2]

### E：蒸馏可执行能力，而非预先命名的能力标签

\[
\hat y=E_{r(o)}(x),\qquad
\min\ \mathbb E[\ell(\hat y,y_T)]+\lambda C_{\mathrm{deploy}}.
\]

可选教师目标包括 A 中的深层近似残差、B 中的实际纠正增量。标量刷新收益头属于 A 的控制器；除非单头确有条件异质性瓶颈，不必强行专家化。

**知识蒸馏、条件计算、功能可分解，是不同层次的命题。**本包先测前两者，不把后者当作已知事实。[R10,R11]

## 4. 首选路线不是固定流水线

```text
读取真实状态、授权和已有证据
              |
       WorldCache 当前未决问题
              |
      固定调度的近似诊断/确认
         /          |          \
近似已有净收益  刷新安排有空间  残差可学且单近似不足
     |             |             |
确认/必要W2       W3          E-W 单学生
     |             |             |
     +-------------+-------------+
                   |
         选择一个主候选做独立确认
                   |
             泛化与论文证据

OMR：资源核对可并行，不占主要生成槽
  资源就绪 -> O0本地复现 -> O1/O2/O3最小筛查
  获得更强证据时，可在批次边界替换主执行槽

  可并入E-W或E-O；通过独立升级门槛后另立主线
```

W1 没有净收益时，不必把 W2、W3 和 E-W 都试完才允许转向 OMR。反过来，OMR 尚未解锁时，不应为等待它而强行训练随机 adapter。

## 5. 三种执行状态与资源分配

### 5.1 状态 A：WorldCache 仍是主执行

主要 GPU 预算投向当前 W1 结果的确认或最近的机制瓶颈。OMR 只做资源和配置核对；E 优先读取已合法获取的数据，做 CPU/低成本分析。

建议管理比例为：**约 80% 投主候选、20% 保留给诊断和后备筛查**。E 的探索从这 20% 内支出，不额外叠加；没有合格后备任务时不必把保留额花掉。这只是预算分配建议，不是每周必须达成的比例。

### 5.2 状态 B：OMR 就绪且值得比较

在 WorldCache 当前有界批次结束后，允许给 OMR 一个最小筛查批次。仅在 OMR 的实际收益、复现可靠性和新增成本更有利时转移主执行槽。

**不要因 WorldCache 一次不涨分就切换，也不要因沉没成本长期拒绝切换。**优先选择最能消除关键不确定性的下一项实验。

### 5.3 状态 C：已有独立确认的候选

至少约 80% 新研究预算转向该候选的强基线、公平消融、冻结测试、迁移和论文材料。暂停没有明确必要性的加模块；其他方向保存可恢复状态。

### 5.4 专家化升级不新增无上限并行槽

E 被证明更有价值时，可以替换 A 或 B 的主槽；不会自动变成第三条同期开大批实验的任务。独立升级的条件见 §10 与 03。

## 6. 预算：统一总账，而不是每份文档各开一笔

### 6.1 计量

\[
C_{\mathrm{GPUh}}=\sum_j g_jt_j/3600,
\]

\(g_j\) 为实际占用卡数，\(t_j\) 为占用秒数。两卡运行一小时计两 GPU·h；并行变短不意味着总成本减少。

同时记录 GPU 型号、端到端时长、原生单视频等价量 FVE、标签/训练/评测/失败成本。不同硬件的 GPU·h 不能直接当作等价算力收益。

### 6.2 建议提报窗口

| 窗口 | 建议上限 | 内容 |
|---|---:|---|
| 只读接续 | 不新增 GPU | 状态、权限、可复用结果与源码映射 |
| 首个技术/科学小批 | 至多 4 GPU·h | 当前主线最小缺口；已有结果不重复 |
| 一个自主执行窗口 | 至多 3 轮且累计至多 12 GPU·h | 仅限明确获准范围内的实验卡 |
| 首轮可行性复盘 | 新增累计约 20 GPU·h 时审查 | A/B/E 共用一笔总池，不是每条各 20 |

**以上全是提报建议，不代表用户已经批准。**实际执行取项目已有更严格上限；无明确授权时完成计划和代码检查，停在 NEEDS_APPROVAL。某原子任务预计就超过上限时，先缩小或提交成本，不强行启动。

样本规模是阶段上限，不是预算无限时也必须全部完成的清单。达到预算上限可以形成有价值的部分结果；预算不足不等于科学失败。

### 6.3 不容忽略的成本

反事实分叉、教师深层真值、梯度教师、prefix 重放、恢复快照、解码、外部评分、张量落盘、额外网络输入提取、编译、失败重试和移植工程必须计入。

“Head 只有几千参数”不能成为跳过标签成本审批的理由。特别是 cache 步的真实深层 residual 原本不存在；额外获取它不可能凭日志开关变成零成本。

## 7. 统一实验门槛

| 门槛 | 科学问题 | 正面证据 | 不足时的合法解释 |
|---|---|---|---|
| G0 技术与测量 | 改动可被公平测量吗？ | 禁用一致、无标签泄漏、状态与计时可信 | TECH_BLOCKED，不记方向失败 |
| G1 机制空间 | 有东西值得优化吗？ | 近似可改、有限调度候选更好、教师有效或专家互补 | 审查候选/指标/样本，不硬加网络 |
| G2 低成本可利用 | 廉价可观测信息能预测吗？ | 分组验证优于强简单基线 | 区分信息不足、模型不足和数据不足 |
| G3 端到端收益 | 开销后还有净收益吗？ | 实际质量—时间前沿改善 | MECHANISM_ONLY 或 NO_GAIN_IN_SCOPE |
| G4 独立确认 | 是否只在开发样本有效？ | 冻结样本/新种子/合理区间支持 | INCONCLUSIVE 或缩小主张 |
| G5 工作完整性 | 有投稿级完整证据吗？ | 强基线、消融、迁移、失败边界、资源成本 | 补最关键缺口，不堆全部模块 |

**不要把误差重尾直接等同于可修复的终点质量重尾。**重尾只触发诊断；是否刷新有用，必须用实际干预或合法对照确认。

**不要把单学生成功等同于专家化成功。**MoE 必须超过参数/激活成本匹配的单学生与时间阶段基线。

## 8. 下一项实验的选择规则

按顺序检查：

1. 任务是否在授权和资源内？依赖未满足则不可执行。
2. 是否已有兼容证据？有则直接复用，不为阶段名重跑。
3. 是否能回答当前最关键且尚未知的问题？优先最小判别实验。
4. 同等信息价值时，优先更接近真实质量—时间结果、复用更多资产、成本更低的任务。
5. 相似工作是否已覆盖该改动？覆盖不自动否决，但必须明确基线和新增证据维度。

这是决策顺序，不为未知成功概率虚构数值评分。

### 8.1 典型条件分支

| 最新观察 | 主下一步 | 不应做的事 |
|---|---|---|
| W1 固定调度与端到端均有效 | WC-C1 独立确认 | 先加 MoE 再确认 |
| W1 局部误差有效但端到端无收益 | 检查误差传播/测量与尾部样本 | 直接写质量改善 |
| W1 剩余误差具局部分组结构 | WC-W2 | 同时加入新 scheduler |
| 同预算刷新位置确有终点收益 | WC-W3A/B | 只看局部误差训练风险分类器 |
| 缓存残差可学，单规则近似明显受限 | EX-W1 单学生 | 直接蒸馏整个生成器 |
| OMR 资源到齐、WorldCache 证据停滞 | OMR-O0/O1 最小筛查 | 等 W2/W3/E 全部试完 |
| OMR 教师有效、无训练简化后仍贵 | EX-O1 单执行器 | 蒸馏没有本地效果的教师 |
| 专家之间无交叉优势 | 保留单学生或并回宿主 | 强行均衡路由制造“专业化” |
| 专家有优势，廉价路由取不到 | 检查可观测性/固定阶段基线 | 在线先运行所有专家再选最优 |

## 9. 有效研究周期，而非硬性日历承诺

沿用旧计划 12–16 个有效工作周的规划视野，但按真实进度跳过已完成内容；GPU 排队或资源阻塞不算科学进度。[P1]

| 里程碑 | 建议重点 | 必须回答的问题 |
|---|---|---|
| M0 接续窗口 | 状态与结果映射 | 已经知道什么，当前真正未知什么？ |
| M1 首 1–2 个有效研究周 | 当前主线小闭环 | 是否有可信基线与首个净收益点？ |
| M2 第 3–4 周 | 一个条件分支或 OMR 筛查 | 哪条候选最值得集中投入？ |
| M3 第 5–6 周 | 独立确认 | 收益能否跨未见场景与种子复现？ |
| M4 第 7–10 周 | 强基线、消融、最小迁移 | 到底是哪一项机制有效？ |
| M5 第 11–16 周 | 冻结评测与写作 | 支持哪些有限主张，哪些不支持？ |

如果 M1 已有坚实有效方法，不要求等待 M2 才开始确认；如果资源长期阻塞，可先停表并切有依据的后备，不把日历拖延写成科研失败。

## 10. 合并、独立与论文边界

### 10.1 A 与 E-W 合并

条件：残差学生确实减少缓存失真或允许更少刷新；专家化额外改善已过公平对照。最终可以只有单学生，不必 MoE。

候选研究主张：在特定缓存状态分布和观测成本下，学习残差或条件专门化优于无训练近似。必须比较 DisCa、LESA、OnlineCache 中相关机制。[R5–R7]

### 10.2 B 与 E-O 合并

条件：OMR 教师在本地有效；学生低成本逼近实际纠正动作；相同真实时间下超过稀疏/复用教师基线；不是单纯让学生模仿无效方向。

候选主张：用少量教师刷新和可预测的纠正动作，保留教师收益。教师蒸馏目标是“纠正增量”，不是全模型能力已经解耦。

### 10.3 E 独立升级

至少满足：清晰的专门化科学问题；公平单学生对照；独立数据上的交叉优势；廉价路由恢复足够收益；净质量—时间改善；第二个设置支持适用范围；与阶段专家已有工作有具体区别。

第二个设置可以是同类任务上的第二主干，不强制同时实现 A 和 B。跨宿主复用的是方法和训练协议，不默认共享权重或 latent 坐标。

### 10.4 A 与 B 组合

只有两条各自有效、接口兼容且有额外研究预算时才测试。组合需要单独数据和 `Native / A / B / A+B` 对照。

OMR 改变 latent 后可能使缓存及其校准失效；先保守失效/刷新并记入额外成本，再讨论保留。缓存改变 clean estimate 后也可能改变 OMR 教师信号。不能把两边独立加速比相乘或分数增益相加。

### 10.5 不使用伪分解

此前讨论里的 `E_cache = E_approximation + E_allocation` 只能作口头分类，**不是无条件成立的精确等式**。本包用固定策略、固定近似器和 2×2 因子对照分析交互，不用该式推导理论保证。

## 11. 停止、修订与自治边界

一次最多一个昂贵 GPU 任务；若任务本身双卡分片，它仍是一项任务，但计两卡成本。是否允许并行小型 CPU 分析，由现有项目权限决定。

等待、轮询、日志基础解析、计账由确定性程序完成；不为检查 GPU 进度反复调用模型。每个完成事件至多触发一次主要分析。429 时持久化状态并停止，不无限重试。[P5]

三个**没有减少关键不确定性**的有意义实验触发方向复盘，不把“三次分数没涨”机械等同于无进展。技术失败、证据不足、机制成立无净收益、范围内无收益要分开记录。

新 backbone、主干/adapter 训练、付费评分、扩大数据、外部发信和改变研究主张都需要相应权限或明确审查。不能由“总计划里写了后续路线”推导全部执行许可。

## 12. 第一批交付与完成定义

第一批只需完成：真实状态映射、可复用资产清单、当前主线一张可执行实验卡、OMR 资源状态、E 可复用数据清单，以及在已有授权内完成的最小缺口。

每次报告固定包含：问题、唯一主要改动、样本与配置、所有结果、真实成本、证据状态、失败解释、一个最值得执行的下一任务。更新当前项目的 CURRENT_STATE、HYPOTHESIS_LEDGER、EVIDENCE_MAP、DECISION_LOG、NEXT_ACTIONS 与 handoff；不新建第二套自治框架。

本研究盘子的完成目标不是“三个方向全都做完”，而是**在有限资源下选出至少一条有可重复质量—时间收益、机制可解释、证据边界清楚的工作**。
