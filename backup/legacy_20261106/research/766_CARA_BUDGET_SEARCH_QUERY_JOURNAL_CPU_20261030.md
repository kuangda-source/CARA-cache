# 预算搜索查询日志与恢复的本地CPU接受

2026-10-30。[765搜索组件](765_CARA_BUDCACHE_BOUNDED_SEARCH_COMPONENT_CPU_20261030.md)的原源码保持不变，新增独立查询日志层，完成14项本地文件系统与进程控制。已记录的评价返回可用于重建搜索状态，不再调用评价器；缺少返回的原查询保持UNKNOWN，不自动重做。真实Cosmos评价、原运行终态读者、专用存储及双端生产CPU仍待，当前不能派发GPU搜索。

## 已实现的恢复语义

[日志组件](../src/wcomr/cara_budget_search_journal_r1.py)持有整个控制器期间的文件锁，绑定搜索配置、上下文摘要、调度/profile、FIT顺序、Python版本及控制器/日志/语法源码。新目录和每份记录均执行独占创建及文件/目录fsync；原目录不覆盖。回调之前先保存完整查询意图，回调返回后保存带请求摘要和内容摘要的RETURNED记录。回调异常单独保存原错误，既不重试，也不把异常当作GPU进程已经终止的证据。

恢复时使用相同控制器、随机源和参数从头重建状态，逐条核对请求身份并读取原返回。旧查询仍占原总额度，恢复不会获得第二份查询上限。默认仅恢复；到达尚无意图的新查询时停在NEW_QUERY_NOT_ADMITTED，不写入意图。调用方明确允许新查询后，也只能继续原连续序列的未执行尾部；此布尔开关不是GPU授权，实际生产入口仍须绑定原准入与guardian。

已有意图但没有返回时，停止为ORIGINAL_QUERY_UNKNOWN_NO_DISPATCH，保留原编号和已完成候选。返回写入失败同样保持未知；部分文件、断号、无意图的返回、内容摘要变化、配置/上下文变化均拒绝，不删除或修补原证据。下一步的生产读者必须核对原物理请求终态，再处理这类未知；本版本没有添加人工伪造完成或重试接口。

## 实际验证

[验收CLI](../scripts/check_cara_budget_query_journal_r1.py)先校验765回执中的全部源码哈希仍一致，再执行[14项测试](../tests/test_cara_budget_search_journal_r1.py)。[机器回执](../reports/cara_fast_BudCache_query_journal_CPU_r1_20261030.json)记录源码、测试计数及保留在忽略目录的10份实际日志文件摘要。

- 完整4查询合成执行后，以默认只读恢复再次运行控制器：4份返回全部复用，新增回调0，查询轨迹与全部日志字节保持，终态仍为原额度耗尽。
- 真实子进程在首意图写入后以exit17退出；父进程重新打开同一目录时锁已释放，原查询保持UNKNOWN，新增回调0。
- 一份返回完成后、下一意图写入前中断：默认恢复停在原尾部；显式允许后只执行2、3、4号，1号不重算。
- 回调异常、非有限序列化、错误返回身份、磁盘满、部分意图/返回、断号、孤立返回、变更上下文/seed/上限、重复创建及并发锁冲突均按各自边界停止。

这些是本机真实文件和进程上的合成评价控制，未运行模型或生成视频。CALLBACK_ERROR/RETURNED描述回调返回情况，不能替代物理进程退出、真实RGB来源、技术验收或费用结算。`attempted_cohort_evaluations`仍是控制器的逻辑查询访问数；新回调数、复用返回数和已持久化意图数另列，不能把恢复访问重复记为新GPU消耗。
