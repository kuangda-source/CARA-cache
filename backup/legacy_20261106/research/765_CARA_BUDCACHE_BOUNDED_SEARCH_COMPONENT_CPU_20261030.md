# BudCache式预算搜索组件的本地CPU接受

2026-10-30。已实现同Cosmos36更新、19D配额下的SA与采样HC控制器，完成11项本地CPU控制。该组件填补[764源码核查](764_CARA_BUDCACHE_PRIMARY_SOURCE_AND_QUERY_SCOPE_AUDIT_20261030.md)之后的搜索执行缺口，真实Cosmos终点评价、持久化查询恢复和双端生产CPU仍待完成。本轮没有模型调用、真实视频、GPU提交、预算预约或账本写入。

## 实际实现与原合同

[搜索组件](../src/wcomr/cara_budget_search_r1.py)在入口绑定原R2调度网格、profile指纹和两个FIT身份，拒绝CHECK、改网格或改profile。候选由原生产语法编译，固定19D/17C、两分支同读出，保护1–7、24、36；每轮从当前mask生成全部合法单交换邻域，因此能够走出初始布局的一次交换范围。SA最多200轮，采样HC最多5轮，每轮至多20邻居；重复候选继续消耗查询，没有暗中启用缓存或平坦损失提前退出。

起点是原冻结Uniform19，策略指纹 `d552b5b12c142475746edaed06d15f0a33db4d35511df7ac52f92e990dc92a25`。首次测试发现，将24提前加入最远点初始化的保护集合会改变整套起始布局；实现已修正为沿用原Uniform19，再在后续交换中保护24，原源文件和冻结策略未修改。

搜索使用独立Python随机源，生成seed仍为0。HC候选去重后排序再采样，使序列不依赖全局随机状态。这些与官方Wan随机前缀起点、随机源处理及缓存读出的差异按[原适配提案](../plans/cara_next_stage_20261028/mainline/r2/BUDCACHE_ADAPTATION_R1.json)披露，名称仍为BudCache-style SA+HC with CARA-C readout，不声称完整官方复现。

## 查询和失败语义

一次查询必须返回两个FIT的完整非负有限RGB MSE，按输入等权聚合。请求摘要绑定上下文、序号、阶段、策略和FIT；错摘要、缺成员、重复成员、未完成、NaN、无穷、负损失或评价器异常均停止，失败尝试计入查询额度，保留此前最佳完整候选且不重试。摘要回显本身不证明真实视频来源；生产评价器仍须验证源、请求、教师和RGB身份。

每个查询在调用评价器前计入内存日志。达到上限后不再调用评价器，HC中途截断也保留此前所有完整评价中的最佳候选，明确标记QUERY_CAP_REACHED。程序正常完成固定迭代也不声称数学收敛。内存日志不具备跨进程恢复能力，当前组件不能独立执行真实GPU搜索；原查询的持久化意图、终态和无重试恢复是下一项必须补齐的生产边界。
