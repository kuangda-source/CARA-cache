## 发现与价值

原正例和新负例的刷新前状态有明确差别，值得进行一次有限的区分实验：

| 刷新前条件与结果 | seed0旧正例 | seed1新no-op | seed2新负例 |
|---|---:|---:|---:|
| 当前 solver step / CFG槽 | 23 / 1 | 23 / 1 | 23 / 1 |
| 本槽上次真实完整计算 | 21 | 22 | 22 |
| 本槽缓存年龄 | 2 | 1 | 1 |
| call45后另一CFG槽上次完整计算 | 23 | 23 | 22 |
| 另一CFG槽本步实际动作 | D | D | C |
| 当前原生建议 | C | D | C |
| 快照前完整调用CFG0/1 | 10/10 | 11/10 | 10/10 |
| 最终signed LPIPS（BASE−REFRESH） | +0.011927 | 0 | −0.012122 |
| 当前额外完整调用 / 严格未来节省 / 全程净节省 | 1 / 3 / 2 | 0 / 0 / 0 | 1 / 0 / −1 |

**seed0的D46把本步两CFG变成D/D；seed2的D46把C/C变成C/D。** 这提出一个比“年龄大就刷新”更具体的候选解释：单独刷新一个CFG槽可能改变两槽误差的组合，而联合完整计算的效果可能不同。年龄也同时不同，所以当前三条记录不能确定哪项条件导致终点差异。模型上下文指纹与记录的指标协议相同；旧forced-C的真实输入、输出、缓存、求解器与OFF一致，因此旧C与新BASE的动作定义可对齐。新runner根中没有单独记录全部WC运行设置，不能仅凭模型指纹声称跨源码所有设置均已独立比对。

下一项有限区分可在**同一个seed2、同一step23、同一完整快照**比较原C/C、单槽C/D和联合D/D；保持缓存年龄及当前去噪阶段，比较联合刷新相对单槽刷新、相对原WC的终点与总成本。联合仅修复单槽的额外失真而仍输给原WC时，只能算修复信号。新假设需另卡登记和CPU恢复/重复/真实入口检查，不能追认为本轮已验证。

## 未来计算并非简单延长一个缓存周期

seed0在严格未来calls47–72中有6次D→C及3次C→D，净省3；seed2有4次D→C及4次C→D，净省0。两者都重新分配了未来动作，不能把计数变化唯一解释成“缓存寿命延长”。这些未来动作是干预后结果，不可输入当前决策器。
