## 已定位的四卡适配要点

1. 旧 lifecycle 硬编码两卡 SSH 别名、Python 和工作目录。新入口沿用已验证四卡 native Python wrapper；host 子进程不能误用 wrapper 内原始 `sys.executable`。
2. 旧 CPU 部署从原 CAL12 stage 复制并要求同父目录。四卡需用原字节输入与新主机 registration 重建依赖，保留原科学配置。
3. 旧 `require_BANK24` 直接调用历史验收器；当前 BANK24 使用独立 Ada attempt 身份及 host/container 财务协议。后续接入必须从完整终态原件重新验收并绑定该 launch，不能只读取一个通过标志。
4. 旧 supervisor 直接启动 host GPU 子进程并传递 FD。四卡应复用已有跨容器锁/peer/退出/结算设计，为 1624 建立自己的完整生产 CPU。
5. 环境复用固定 CUDA 库和物理 NLTK 资源，但原四 CAL 的入口 scope 为 `CAL12`，不可机械继承 BANK24 的环境值。
6. 完整新 CPU 包括两 flow 共 28 路径、4060 格原件重读、生产入口和 12 项缺 guard 拒绝；最终 CPU post/collector 与只读账本接口也须适配。
7. 已有 12 GPUh 批准保留。原 9.918 小时仅是旧机整卡规划；新报价必须完整覆盖额外采集，不能用 BANK24 普通视频耗时直接代替。

原整卡估算约 49.0 GiB 原张量、93.5 GiB 最低可用磁盘、17.1 GiB 峰值锚点库；原准入公式要求约 26.2 GiB 可用主机内存。约 1.88 TiB 是累计源搬运量，不是同时驻留或磁盘需求。这些为原估算，下一次准入以新鲜资源检查为准。
