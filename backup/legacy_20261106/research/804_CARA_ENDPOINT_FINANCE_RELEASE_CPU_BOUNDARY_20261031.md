# 804 — 端点费用与释放承接CPU边界

新端点卡的原费用、唯一结算和释放后完整集合承接组件通过33项本地CPU控制（17项新端点控制＋16项原生命周期回归）。真实临时账本I/O验证失败仍结算、重复接受不新增费用、旧16.5GPUh责任保持，以及原句柄未知/未退出、锁未释放、模式未恢复、未结算均在读取集合前拒绝。本轮未派GPU、未访问或修改中央账本，未操作正在运行的14GPUh原卡。

新生命周期读者沿用预算卡已验证的财务与原句柄机制，保留原launch SHA、注册/授权/源码字节、四原进程PID/start ticks与host view、原容器及单卡身份、guardian完整单调时钟、唯一中央账本前后状态、Default恢复与原释放快照检查。为保持在运行预算卡的已登记源不变，端点读者单独版本化，只替换自身来源路径、新卡guardian终态标识和返回字段；AST控制证明其余逻辑与原读者一致。当前尚未将新标识接入新卡生产guardian，不构成完整生产编排接受。

财务终态与科学接受分开：CPU夹具中的失败容器及缺失集合均保留0.05GPUh合成原费用，并在临时账本只结算一次；结果不成功不会免除费用。原CPU夹具不能进入生产模式；未知进程、缺失终态证据或未证明的锁关闭也不能被当成已退出。

完整集合承接先重建财务与资源释放，再核对新端点授权、当前card与binding摘要、原预算冻结SHA、原预算与端点不同launch、注册清单中的原card/binding字节和读者/执行源。之后才读取完整32或合法去重25的有序集合，检查36更新、实际策略动作、零回退、清洁计时与原runner记录的集合摘要。任何缺失位置、换序或原runner摘要变化均拒绝。通过状态仍明确为工件验收待完成，没有自动赋予评分或新GPU权限。

下一处评分承接必须保留跨运行来源：新候选属于新端点scope，旧Native35参考和12份旧评分属于原A32/B36接受scope。现有评分入口要求同scope，因此新入口需显式验证已冻结参考、相同输入/seed/模型/精度及九项重放身份控制，保留两侧原身份；不能通过改写旧scope来复用原入口。旧指标不重算，预算别名只映射到同一个新评分对，不能形成额外独立样本。完整32或去重25的报价仍等真实预算冻结确定后再冻结。

剩余工作为新卡guardian/runner真实接入、完整工件与九项RGB控制、跨运行评分清单/一次评分及独立接受、实际最终预算mask的受影响CPU、最终源与完整报价。当前单次14GPUh原实验及其23:16半程、次日06:01终验、06:45:04硬截止保持；本轮没有重新观测其GPU状态或读取部分科学分数。
