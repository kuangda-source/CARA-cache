# CARA：主线收束与 CFG 调度／缓存压缩实验总计划

日期：2026-10-27。仓库观察基线：`88406a054d90066bbb8970c5dce256ea0341a16a`。

性质：研究设计与优先级更新。不是新科学结果、执行授权、预算预约或运行状态。原始合同、失败、费用和冻结配置不修改。该计划不要求通过 R4 新读出才能推进主线。

## 1. 主线、第二贡献和探索必须分层

**已建立的实证主线：** Shared25-C 的刷新放置在固定 Cosmos UniPC/Karras 设置、16 新 DEV 上有效。下一阶段要补公平 WC/RA 对照、独立最终确认及同模型换步数／第二骨干。不要用新模块不断替换已经成立的工作点。

**优先的方法增强：** CFG 相关性是否在相同读出、相同 D 配额和相同校准预算下，改变并改善刷新计划。使用离线共享计划即可，不要求在线控制器或新网络。

**第二候选贡献：** 固定计划、固定模型，仅改变跨去噪步的特征缓存编码，检验 CFG-aware 编码／位宽分配在同实际字节下是否优于独立分支量化。第一目标是失真—存储优势，不预先声称加速。

统一科学问题：有限资源应该按**实际 guided 输出误差**分配，而不是只按各分支独立误差分配。调度分配时间资源，压缩分配表示精度。二者共享误差几何与资产，但先分别验证，禁止直接合并成一个无法归因的全方法。

## 3. 重要程度与执行依赖

| 优先级 | 工作 | 重要性／可行性 | 先交付什么 |
|---|---|---|---|
| P0 | 双计时、Native vs wrapper-allD、合理WC/RA基线（复用725） | 最高／高 | 原73槽合同及实际路径一致性，不重复新建卡 |
| P1-A | CFG调度判别实验 | 高／中高 | CPU矩表与掩码是否可辨识；缺标签才申请共享采集 |
| P1-B | 冻结Shared25最终确认＋Q5换步数 | 高／高到中 | 保护最终输入；Q5先检查规则／模板是否产生不同布局 |
| P2 | CFG缓存压缩 | 中高／离线高、部署中 | 同字节编码筛查→真实readout→仅胜出者视频 |
| P2后续 | 第二骨干 | 高／中 | 同流程重校准，不重新手选步号；预算单独冻结 |
| P3 | R4共同长龄、局部到终点干预 | 中／中 | 可复用资料先分析；新GPU仅回答未解问题 |
| P3 | 19D高速第二档 | 中高／中 | 主基线明确后，与同D数C/A对照；不和压缩同时改 |
| P4 | Cosmos本体量化、单支刷新 | 潜力高／工程成本较高 | 后端与成本先验证；不进入当前两线实验 |

重要程度不等于先后串行：协议准备、旧资产分析、Q5的CPU可辨识性可以并行；只有一项重GPU任务运行。最终确认可保留既有Shared配置，不必等所有探索成功。若新的调度候选要入最终主表，必须先开发冻结，不能拿最终输入帮它选规则。

## 4. 资源保护

最近已知IG结算快照：used172.2657747142，reserved16.5，available37.2342252858 GPUh；不是实时账本。用户允许总上限按24GPUh增量并通知，但当前cap仍须以实际账本为准；这不等于任何新GPU卡已授权。

按约37.23GPUh做不重叠规划：协议桥接最多12、最终确认保护10、共享采集目标3、调度小闭环目标3、压缩readout目标1、Q5目标3，余约5.23作为失败／补完余量。以上为预算规划，不是硬报价。Wan迁移与压缩完整视频不能同时假装已被这份预算覆盖；有正结果后调整低优先项或按既有规则增加cap，并另行申请卡级执行。

**压缩CPU分析不等价于零成本：** CPU/I/O、原件读取、codec实现均计资源。新增模型调用要计入共享采集，而不是分别在两条线报“免费”。

## 6. 同期文献的定位

RA-CFGCache v1为2026-09-29。CVPR2027作者指南把2026-09-15起首次公开的工作通常视为同期，但要求引用、讨论、合理可行时比较，且实际影响投稿的工作仍计prior work。因此不追求为避开RA而完全不同；承认共同问题及已有RA本地实现，明确本项目离线预算化分配、缓存表示精度和实际机制的增量。

CacheQuant已研究模型量化与缓存调度共同优化，不是这里跨去噪步激活缓存的同字节CFG编码对照；引用它，避免宣称“缓存+量化”首创。自回归视频KV压缩也应与当前残差缓存区分。
