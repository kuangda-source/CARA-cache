# Q：CFG-aware 跨去噪步特征缓存压缩

状态：独立候选设计，不是本体量化、AR KV压缩、单支刷新或新读出融合。主模型权重／激活计算精度、Shared25-C布局及WC-C读出保持不变。

## 1. 第一目标与压缩对象

第一目标是在**相同实际缓存字节数**下减少guided误差，或在相同失真下减少缓存字节。第二目标才是显存峰值与实测速度；不得把文件压缩率等同GPU加速。

首轮只压实际C路径消费的两支`residual_cache / residual_window`真实锚点残差r；所有必须用到的窗口项都编码，不能只压一个从未被读的副本。probe残差p与solver状态保持原精度，其字节仍计入总缓存。不是先改成d缓存，因为这会同时改变读出机制。

D在当步仍返回未量化完整输出；在两支完整pair提交时编码未来复用的r。来源仍可追溯为完整BF16计算，但存储表示标记lossy，不把重建源当成误差为零的真值。评估用原始未压张量只作离线teacher；部署不能同时保留它而宣称节省显存。

## 2. 两支编码与正确的CFG边界

令m=(r_c+r_u)/2，delta=r_c-r_u。分别编码后还原r_c=m+delta/2、r_u=m-delta/2。

在实际输出坐标中，e_g=e_m+7.5e_delta，误差平方含共同项、56.25倍差分项和交叉项。

但隐藏cache之后的两支warp/head/RF通常不同。局部线性化为：

    delta_vg ≈ (8 Jc - 7 Ju) eps_m + (4 Jc + 3.5 Ju) eps_delta。

只有Jc=Ju等特殊条件才退化为同一个J作用于eps_m+7.5eps_delta。因此**不能只按隐藏差分7.5倍固定bit分配**，也不能预设“差分一定多给bit”。需通过真实C读出、实际输出CFG评分，数值范围、相关性与归一化同样重要。

## 3. 最小codec与同字节对照

固定每token的通道轴连续128值一组，尾组按真实元素计；对称minmax/absmax均匀量化，rounding、clamp、zero-group规则和scale dtype在输出前固定。首版scale为FP32，每组4字节，整型payload实际打包；4bit须真正两值一字节，不以BF16 fake-quant张量充当压缩存储。统计分支顺序、shape、布局、padding、headers、alignment与scale成本。

只研究4/8bit，避免同时引入SVD、随机旋转或熵编码。

| 预算档 | 独立分支表示I | 共同/差分表示M | 比较意图 |
|---|---|---|---|
| 原精度 | 原r_c/r_u | 不量化的m/delta往返 | 往返舍入与正确性，不宣称严格无损 |
| R16 | (8,8) | (8,8) | 同payload下只改变表示基底 |
| R12 | (4,8)或(8,4) | (4,8)或(8,4) | 同payload下位宽方向分配 |

R16/R12是每对对应元素的名义payload位数；精确比较使用实际packed bytes加metadata，两表示必须使用相同group、shape和对齐策略。原张量实际dtype现场读取，不能默认BF16。整体压缩率的分母包含未压的p/solver/工作缓冲，峰值还包括临时重建张量。

## 4. 2×2：表示基底与CFG目标分开消融

R12在相同候选集合下比较：

| | 按平均分支误差选位宽 | 按实际guided误差选位宽 |
|---|---|---|
| 独立分支I | I-BR | I-CFG |
| 共同/差分M | M-BR | M-CFG |

每种方法只在训练prompt上选一套全局bit方向，跨请求使用同规则；量化scale由当前待编码缓存计算，合法且不含teacher。不得每个测试状态用teacher选择codec。

主比较优先M-CFG vs I-CFG（最强合理独立量化），M-CFG vs M-BR（目标是否重要）。如果BR与CFG最终选同codec，则该目标增量为零，不重复视频。同名义码率但实字节不相等时，先匹配真实bytes，不奖励更大存储。

## 5. 已有张量 → 真实输出的两级筛查

Q0：复用B1原件，CPU构造codec，记录raw重建、共同/差分能量、字节和roundtrip误差。raw筛选只能排明显数值问题；不能因分支MSE较差而直接淘汰可能更好的CFG编码。

Q1：在相同当前状态与同一份源窗口上，将所有受压窗口项解码，走真实WC-C warp/head/RF。teacher与未压C在两线中只算一次。最多四个R12角色加两个R16角色；先训练折筛掉完全相同codec，再重放少数不同代表。无新deep生成不等于免费：模型驻留、head、读取和写盘全部计费。

记录：
- q_total=||v_Q-v_D||²；
- q_codec=||v_Q-v_C||²；
- 2<e_C,v_Q-v_C>及三项之和；
- 两支误差矩、梯度残差、高频能量诊断；
- 真encoded bytes、全部持久cache bytes、peak allocated/reserved、encode/decode wall。

压缩误差可能偶然抵消原缓存误差，因此不能只报q_total变小；需报告增量误差，并用留出prompt及完整视频确认。

## 6. Q-END：固定Shared25-C，不同时改D或A

仅在Q1同bytes有明确空间且真实部署codec可用后开展。

四旧CAL×{未压C、冻结最强独立量化、M-BR、M-CFG}，最多16正式角色输出；等价codec去重。可先选一个目标码率，不能把两码率、SVD、调度联动同时塞进首卡。Native缺格、原强参考、warm、重复和质量评分另计。

参考同时报告：d(Q-CARA,N_BF16)、d(CARA,N_BF16)、d(Q-CARA,CARA)。最后一项不是总保真主目标，三项不能直接相加。

沿用原MUSIQ/主体/运动与完整请求预算。建议研发目标：同bytes有跨prompt一致误差改善，或在不显著破坏质量下达到约2×目标payload压缩；这些是探索目标，不替换旧门槛。即使提速为0，只要实际cache/峰值收益明确可定位为memory-fidelity扩展；若仅小文件缩了、持久cache/峰值/速度均无实用改变，则不当核心贡献继续放大。

## 7. 成本门与后续联动

新延迟 = 原延迟 + 编码费用 + 各复用解码费用 - 真正省掉的带宽/搬运费用。不能预设右侧为负。上线不得在每步重新量化所有历史或同时保留整套原精度影子。

若只有降低显存的收益，报告为压缩，不让它背负1.5×速度目标。只有调度线和压缩线分别成功，才追加2×2：Shared vs CFG计划 × 原精度 vs 冻结codec。部署缩短时间、增加batch或更高分辨率是另一个可检验目标，不混到当前单请求速度。

Cosmos权重量化不属于本卡，避免与组内PTQ重复；后续可作为正交组件，先有真实低bit内核再谈加速。
