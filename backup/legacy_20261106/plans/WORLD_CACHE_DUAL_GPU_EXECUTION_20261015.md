# WorldCache双卡执行与结算约定

用户2026-10-15明确授权双卡锁与记账兼容修正，并在空闲卡执行同26D主线控制；原预算、少于12GPUh自主规则、长任务按ETA一次查收保持。当前两任务身份与回执见[450](../research/450_WC_DUAL_GPU_SIMPLE26D_RUNNING_AND_ACCOUNTING_ACCEPTANCE_20261015.md)。本约定覆盖历史“全项目只允许一个GPU作业”的技术限制，不改变任何实验科学范围。

1. **权威预算为v2。** `reports/gpu-budget-v2.json`：实结=origin＋各原任务已结实际GPUh，预留=所有活动任务完整计费上限之和，可准入=原cap−实结−预留。原cap104.971363333、origin79.996377372/94任务不能重置。两GPU同时工作1小时各自计1GPUh，共2GPUh。
2. **每GPU独立长锁，账本只用短锁。** 真实UUID对应 `.sync/gpu-locks/UUID.lock`，持有后fresh核实资源，再在 `.sync/gpu-budget-v2.lock` 事务中预留整个完整任务。源码/配置/CPU/launch ID/范围一起绑定；子进程继承并核对本UUID锁FD。不同任务不能复用run或launch，也不能靠分拆规避授权阈值。
3. **在途旧W3使用桥接。** 原全局f1锁、旧账本和原supervisor不改；独立桥接持GPU1兼容锁，终态后只向v2导入原实际账单一次。旧CPU post终态前不能修改旧账本；之后兼容镜像带永久inflight协议标志，未迁移的旧启动器必须拒绝。不得让新结算被旧快照写回覆盖。
4. **费用如实、失败不重置。** 单GPU任务按supervisor从准入后到子进程清理的实际墙钟费用，包含加载/预热/正式/写盘/清理。CPU post不占用GPU时不算GPUh。重复结算相同原件幂等，冲突拒绝；异常保留预留直至核对原账单，超费记真实数并阻止新准入，不能夹到上限。
5. **自主范围不变。** 原计划内、完整预测和计费上限严格少于12GPUh，可在余额与资源足够时执行；达到或超过阈值问具体完整卡。旧W3单卡12上限有单独直接批准。本卡完整上限8，不另问；不改变累计cap或新开48窗口。
6. **并发时间不作为正式clean证据。** GPU UUID隔离保证任务所有权，不隔离CPU/存储/内存带宽。当前简单调度卡时间为诊断；正式速度实验安排独占且平衡重复。原件等价、端点保真、完整分母仍正常审计。
7. **ETA一次查收。** 不持续监听、不提前看partial科学结果。查收只针对原任务自己的PID/锁/输出/评分/结算；另一GPU合法任务在途不能导致本任务释放判据失败。未完只重估下一时间并结束，不自动重启或续开卡。
