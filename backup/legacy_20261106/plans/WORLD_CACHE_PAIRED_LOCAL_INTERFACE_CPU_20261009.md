# H-T57：同S22成对接口的完整CPU集成

2026-10-09，登记于本轮实现及执行前。Common完整确认已支持H-T52a，但它证明的是当前误差几何。下一步需要区分联合决策的执行方式是否可用，以及刷新是否有终点价值；本轮只回答前者的CPU集成问题，不生成新的科学质量标签。

H-T57a：从原完整父的实际S22／44调用出发，原顺序强制CC或DD与两侧浅层先行后共同选择同一动作，在相同latent、noise、实际条件、缓存与solver历史下，分支输出、原FP32 guided输出和最终可恢复状态相同；显式观察开关不改变这些结果。此假设尚未在2B GPU上验证。

完整范围：重跑H-T55已有60行CPU控制，保留首次失败与尾部修正；新增flow OFF／ON各两完整原父（诊断OFF／ON），每条36实际更新／72调用，到latent而非视频。在ON父的实际S22，CC／DD×局部观察OFF／ON×两严格重复×原顺序／成对顺序＝16局部pair、8比较；两flow共32pair／16比较。原父条件由实际RF构造，临时解除且精确恢复本卡持有的forward／denoise包装，显式记录成对路径的分支观察，不以被绕过的外层hook冒充观察。

局部调用只计算当前速度，不更新solver或父轨迹；每行完整恢复现有缓存／buffer／模式／solver／RNG／generator／冻结条件与原函数绑定。核对实际逐值输出、每层访问、两侧probe在决策时均已支付、无高维truth输入、参数版本、两严格重复和观察OFF／ON，最后核对两完整父逐步输入／输出／状态／终点latent。新增各flow的selector失败和观察器失败，分别验证声明覆盖的恢复与完整父接续；参数变更等任意故障仍不承诺可恢复。

原件保留所有行、失败、分母、配置与源哈希，不接受成功子集。使用真实Torch／上游WC、RF、UniPC代码，模型、条件构造边界、attention、noise等仍是已声明Toy CPU。禁止CUDA初始化、权重加载／下载、预算写入。CPU wall不能作2B加速或显存证据。

后续独立GPU问题拟单真实S22、同8比较／16pair和两原完整父／视频，先准备新collector的生产绑定、源资产、实际CPU与完整费用，再选择身份。不是删减旧五起点机制卡，也不替代全36步候选部署／终点评价。H-T56的1.2905h只是未选定草案；单次>2GPUh仍需具体批准，累计50GPUh不变。原生WC、简单共同刷新和本模型校准RA基线，终点／未来成本标签在后续分别设计；本轮无训练、Head、稀疏扩展、OMR／DRE或人工评审。
