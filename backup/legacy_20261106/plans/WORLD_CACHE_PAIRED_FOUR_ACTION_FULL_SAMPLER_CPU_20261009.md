# H-T60：四动作成对接口的完整36步CPU准备

H-T59确认三条完整原生轨迹都有DC，故下一实现对照须保留CC／DC／CD／DD，而不能用强制共同OR替代原生回放。当前H-T58原CC／DD真实GPU卡照常完成，冻结156载荷不改。本页登记下一CPU比较的完整要求；尚未派发CPU fixture或选择新GPU。

新增独立 `cfg_paired_probe_mixed.py`：继承原生产来源／全局／wrapper拒绝，只将动作合法集合扩展为四种、续算skip改为每槽字符。精确逆AST必须恢复原控制器全部函数体；保护区、初始化／尾部、counter、selector RNG和失败poison逻辑不改。原顺序参照按同一两槽动作替换一个原WC谓词，原函数体其他部分不动。这不是新风险策略，静态编译通过也不是模型等价。

完整新测试应使用实际生产WC／RF全局与官方完整36步求解器，在两种flow、观察OFF／ON、两次严格重复下，比较原顺序／成对执行。动作序列固定为三条已完成轨迹的完整36步mask（H-T59独立结果SHA绑定），再加一个合法区内循环CC／DC／CD／DD的完整序列，以覆盖原数据未出现的CD；保护区仍DD。不根据新CPU结果筛序列。

四序列×两flow×两观察×两重复＝**32完整比较／64全36步路径／2304 solver更新／4608 net调用**。每条完整输出、每步原FP32 guided、输入／条件／RNG、实际层访问、全部状态和五个检查点、最终latent均核对；保护区选择器不应调用，合法区须在两prefix均支付后执行。保留旧H-T58的完整68行与全部失败控制，再加入四动作失败／恢复、顺序／观察／重复与原S22恢复继续对照。实际完整fixture和生产源CPU均通过后，才准备真实2B完整36步卡与费用准入。

本准备未指定终点／未来成本标签，没有用旧mask的OR算术冒充重新生成，也没有用旧曝光mask回放作为可部署政策。若H-T58真实接口出现不一致，先定位并保留该失败，四动作部署不跳过这个问题。新GPU整卡forecast尚未确定，仍按原50GPUh和>2GPUh具体确认约定，不缩拆范围、不训练／扩稀疏或人评。
