本组件将已经完整接受的 B36 32 个评分位置交给人观看。它不计算新指标、不重采视频，也不改变原 A32 冻结、时间匹配标签或旧 CAL 范围。组件本地八项控制见 [CPU 接受](../../../../reports/cara_fast_B36_review_component_CPU_acceptance_r1_20261030.json)。实际原视频复制、传输、页面装配和浏览器检查分别记录；组件接受不代替这些步骤。

## 范围与记录

每份包包含四个旧 CAL 输入、每输入八个原角色，共 32 条匿名比较，包括四条 Native 自比较控制。每条提供同输入 Native 参考与匿名候选，保留原 93 帧、16 fps 和视频字节。按包随机化顺序和不透明编号；公开目录不含方法名、科学分数、时钟、服务器路径或解盲映射。四个参考视频复用，公开目录共 36 份媒体文件，对应 32 个不同原件。

观察维度为内容与动作、运动、可见细节；每项允许更差、无明显差别、更好、无法判断。完整观看声明、浏览器播放范围和备注随 JSON 导出。页面在当前浏览器保存进度；结构完整的导出仍须另行核实审阅者身份、独立性及完整观看，不能自动形成科学接受。

现有包首先供作者诊断。独立审阅者各用新私钥和新包，单独保留返回文件；不把同一作者的重复观看、32 条位置或 93 帧计成独立输入样本。不据此新增事后否决门槛或重选原基线。最终输入与额外 seed 均不在本包中。

## 操作

原视频缓存位于忽略目录 `.sync/cara-fast-B36-review-r1-20261030/videos/`，文件名为原 SHA-256 加 `.mp4`。先确认传输回执为完整 32 份原件的哈希接受，再调用生产 CLI；CLI 会重新核对五份原接受回执，并在创建页面前检查全部视频大小和哈希。

```sh
python3 scripts/build_cara_fast_b36_review_r1.py \
  --analysis reports/cara_fast_B36_complete_analysis_r1_20261029.json \
  --coordinator .sync/cara-fast-B36-review-r1-20261030/coordinator.private.json \
  --output reports/private/cara-fast-B36-review-r1-20261030/public \
  --receipt reports/cara_fast_B36_review_materialized_r1_20261030.json \
  --videos .sync/cara-fast-B36-review-r1-20261030/videos
```

恢复同一包须保留原协调文件。已存在的公开目录和回执不可覆盖；新审阅者使用全新路径，不能沿用本包的私钥。协调文件权限为 0600，留在公开目录之外；只分发公开目录。媒体和解盲文件不提交 Git。

用浏览器打开公开目录中的 `review.html`。浏览器检查仅核对视频元数据、页面导航、填写保存和 JSON 导出，不生成真实人类评分；测试记录须标为 `CPU_TEST_NOT_A_HUMAN`。本地测试与交接使用不同端口的入口，使测试进度不会出现在交接页；测试导出另存忽略目录。实际浏览器验收以独立回执为准。
