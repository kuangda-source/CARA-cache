# 实现边界补充：执行前与主体方案一起读取

2026-10-27。仅设计补充，不是新结果、CPU生产接受、预算或GPU授权。

## 1. 公共采集必须使用动作前的缓存身份

父轨迹该步执行D时，shadow C必须读取执行本次D之前的工作缓存和真实锚点，再结合当前已支付probe。不能先让D写回当前锚点，再用包含当前teacher的缓存计算C。可在动作前复制必要状态；完成实际D取得teacher后，使用隔离的动作前快照计算C，最后恢复实际父轨迹的D后状态。

父轨迹该步执行C时，实际C可复用，额外shadow D只用于标签，不提交其cache、solver或RNG变化。所有teacher与候选API分离。同一prompt的两条父轨迹不是两个独立输入。

公共卡定义中的108位置＝2prompt×2父策略×27目标步；44个额外Dense pair＝4条25D父轨迹各11个C。只在动作前来源合法且有限时评分，缺失保留分母，不能用当前Dense结果回填。

## 2. 不能把局部q(add)-q(remove)当真实终点边际

同状态q只负责生成有限候选。remove/add后，后续锚点、latent和solver历史都会改变。S-END必须自由运行，使用新的轨迹与最终输出。两个父轨迹的平均只是一种冻结提案标定，不能拼成一个真实策略路径。

如果S-CFG与Shared完全同掩码，允许复用同一个视频并保留别名，但不能把别名比较解释为超过Shared，也不能从其对S-DIAG优势推出复杂规则优于简单模板。

## 3. 压缩的校准与验证必须分离

Q1先使用AV28→Human199、Human199→AV28的留一prompt检查：每个训练折只能选择一个共享codec/bit方向，在留出prompt执行；两折结果分别报告。两个prompt仍仅是开发筛查，不进行强显著性宣称。

之后可用两个训练prompt共同冻结一个codec，再做四旧CAL完整视频，另外两旧CAL作为本次机制开发留出单独报告。最终新输入仍使用保护组或另行登记的未用输入。不能按每个测试状态的teacher挑bit分配。

## 4. 量化必须是一次编码、按真实历史持续复用

真实D的原输出仍用于本步更新；未来复用的r窗口在D提交后编码，并记录lossy storage身份。部署不能保留一套未压缩shadow r来提供后续计算，只在离线评估中保留原件。每次解码使用同一个确定性encoded cache，不重新抽样量化误差。

同时核对工作缓存中的张量别名：重复引用同一存储不能被重复计算为显存节省；反之，原r及窗口项各自实际占存储时必须全部列入。报告packed payload、scale/header/padding、所有持久cache和真实峰值。是否减少访存或提高速度用真实入口测，不由压缩倍数推断。

## 5. 两条线不互相设置成功前提

S不要求Q成功，Q不要求S优于Shared；两线都不要求R4产生j1。Q的离线字节分析可以先于协议GPU，但新完整时间结论要使用统一T_DD/T_request边界及相同硬件。
