# COST112失败后：运行时归因、修复及独立验证接续方案 R2

状态：方案，未获重跑授权，GPU提交/新预约为0。用户明确先不重跑。原104/112计时失败保持，不改原α、强基线、部署257.7712338712067秒绝对上限、0.8×fresh Native、固定6秒提案余量或累计226 GPUh。原新P1的14GPUh只是未批准报价；本方案不扩大它，也不把原112授权用于重跑。

## 判断和优先顺序

继续增加单次全D参照或拟合一个统一截距不足以解决本次失败。完整112反事实重放中，64缓存目标改用更近全D或两次全D最大值，最大低估仍3.650秒；不能把被改作参照的8条全D控制留在独立目标分母里。72目标中69条采到热降频，缺少充分冷态对照。

建议顺序是：**运行条件与完整请求时钟稳定化 → CPU生产边界等价 → 冻结修复 → 一次新的完整独立计时验证 → 新P1整卡绑定与完整报价。** 当前不是批准立即再跑112。尚未找到并验证具体运行时修复之前，不派下一张验证卡。

## R0：零GPU的修复准备

### 1. 明确时钟语义和分段入口

现有 `core_seconds` 是 `generate_vid2world` 的完整主流水线，包含条件处理、生成和解码，不是纯去噪CUDA时间。`guarded_pipeline_without_write_seconds-core_seconds` 包含外层文本/视频guardrail及输入/输出转换等；`video_write_seconds` 单独保存视频。现有原件无法再拆出每项的历史耗时。

在独立新模块给以下边界加观测，不改上游、不改原stage：文本guardrail、输入准备、主流水线、视频转换/视频guardrail、编码写盘、安装清理。主流水线内部再按真实方法边界记录条件/编码、采样、解码；名称须依据绑定源码，不凭猜测包装不存在的方法。保存严格嵌套时间戳和父子关系，避免重复相加；所有Native、PG全D、缓存角色使用相同入口。

保留既有完整请求时间边界。CPU-only证明包装返回值/异常/调用次数相同、线程/进程清理完整、计时嵌套不重叠误加、原93帧编码路径与数值控制不变。host单调钟与GPU事件是不同量；异步GPU段不得把未同步host时钟称为GPU耗时。不得在每步加synchronize或用分段观测偷偷改变干净时钟；额外同步只能放注册诊断路径，诊断时钟不能替代正式时钟。正式新增观测应限于阶段边界host时间和已有外层同步，完整开销仍计入。

### 2. 温控：先确认可重复运行条件，不能靠统计删除热样本

已确认原GPU独占，但频率不是恒定的。先只读核对目标卡实际散热/风扇/功率/温控限制配置及机箱环境；当前空闲读数不作历史归因。不能由90°C或35%空闲风扇就断言风扇故障，更不能操作他人进程。

如需管理员改变散热/功率/频率，必须明确记录配置与时间，在所有角色中保持一致；本轮不实施此类改变。优先使用实际具备稳定散热的空闲卡，记录UUID，不能把更换GPU后的系数自然视为已验证。

新卡以注册warm验证运行条件，禁止临时重复warm直至出现满意样本。 proposed新增环境门：20条warm全部计费，最后4条warm若出现热降频，整卡以环境不合格停止、保留完整已执行分母/费用，不进入正式验证、不自动重试；这是一项待CPU实现并冻结的计划，不能倒推用于删旧112样本。正式期间如出现热降频，仍保留全部结果和费用，环境适用性单列失败，不能靠过滤后重新接受。

这项门只检查热限制，不保证频率恒定；功率限制在固定配置下照实记录。若机器本身无法达到此条件，应先修运行环境，不消耗新的8小时证明相同问题。

### 3. 核心外开销：修实现需证据，不移出计时

先用新阶段入口定位外层的波动，再决定是否优化。现有数据只确定外层流程占最坏剩余误差约1.648秒，尚不能指认为某一个guardrail。允许准备确定性的资源预加载/线程与编码参数约束，但其含义、共享给全部角色的方式、初始化是否计费必须写明；不能关闭guardrail、少写帧、把原全请求工作移到未计费背景线程，或只加速CARA而保留旧Native计时。

只读检查I/O和CPU竞争；本卡GPU独占不等于CPU/I/O独占。现在没有同步CPU/I/O利用率历史，不能认定曾发生争用。新采集需要监督侧的低频CPU/I/O记录，费用和采样开销计入整卡，不能与GPU温控混称一个原因。

### 4. 模型修复的约束

不要直接给预测加5.006秒、调小dD或者把6秒改大来“覆盖”这张卡。先保留原冻结模型作为必须报告的对照；没有证明波动源被控制，就不再增加拟合自由度。

若分段证据支持新模型，须在独立验证前明确：哪些特征严格来自目标之前、哪些成本按动作计算、哪些外层费用有独立的预算上界；不得用目标未来时钟或事后温控修正预测。使用112设计/训练即把112列为开发资料，原独立失败仍保留。模型版本、参数、运行配置、最大参照年龄和CPU证明一起冻结。现阶段没有新的已通过模型，也不伪填参数。

## R2：如何接上P1

若受控环境中同策略全D重复本身仍不能稳定满足2秒，不再自动重复整张成本卡。更合理的备选是**实测约束型P1**：价格模型仅提案排序，固定查询内按完整实测请求选可行者，另加预注册的独立重复预算确认；搜索、验证和费用分开记。这仍保留部署/累计预算，但**会改变原“2秒预测门作为P1前置”的合同**，因此本方案仅列为待明确审阅的备选，未启用、未定最终路径数或挪用102报价。不能凭旧112“无假可行”直接批准它，也不能声称旧模型已通过。
