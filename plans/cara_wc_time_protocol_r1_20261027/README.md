## 本轮交付

生产请求统一使用 `wcomr.wc_time_card_r1.Requests`，唯一计时实现是 `wcomr.paper_latency_r1.execute_with_timing`。旧P0时钟原件保留，不在新卡安装；只复用P0的显式WC参数/allD适配。没有叠加两套同步钩子。原 `T_request` 组成不变，`T_generate` 保留；新增 `T_DD` 为连续loop入口至真实decode同步返回。适配编译/安装的外围开销仍进入job计费，不改历史T_request。

[双端CPU接受](CPU_ACCEPTANCE.json)分别绑定实际镜像、源与输出回执：每端两种fixture设置各73登记路径+7 OFF比较，共160条完整小张量路径；七角色全部OFF/ON数值一致，原生Native与wrapper全D一致，Shared25-C动作/alpha不变。每角色还检查text refusal、decode/writer故障、清理和不可重放。生命周期另验完整选择分母、错误Native配对、缺少释放/结算、冻结覆盖拒绝与数值门。模型、attention、prepare/decode和writer仍是声明的CPU小夹具，不能冒充真实GPU等价。

评分方面：两端使用隔离目录复用721已验PIQ0.8.0、VGG和LPIPS权重，真实Alex/PIQ模型CPU加载、自距0与批均值一致性通过。MUSIQ/DINO/AMT/RAFT沿用原已接受构造器和权重绑定，不重写评分器。新科学质量结果为0。

## 执行顺序和硬停止点

1. 批准后发布精确source/config/CPU/quote SHA，恢复两端已有intent；选可硬独占设备，绑定host、UUID、镜像、权重、存储/跨盘日志与中央唯一责任包。不能直接调用硬编码66/128范围的旧启动脚本。
2. A阶段6warm后执行12诊断，`wc_time_diagnostics_r1.verify`对初始网络输入/条件与RNG、逐步guided、最终latent、93帧RGB做精确比较。无完整12条或任一不相等，停止后续8校准路径，保留原件；不事后放宽容差。
3. 数值门通过再跑两CAL的Native/CARA与tau .04/.06。释放GPU并结算之后，用本阶段Native评分4个Alex候选。`freeze_selection`要求完整分母、正确Native对、93帧、释放与结算回执，固定±5%规则选一套共享tau；无匹配则标UNMATCHED，不扩网格。
4. B重新准入、加载、预热，执行4旧CAL×7角色与固定12复测。所有prompt首轮都测时间，复测不是新科学样本。B不再调参；原最终16不得参与阈值/布局选择。
5. B释放结算后跑24Alex+24VGG配对（共4464帧次）、84三质量门位置与28活动度描述位置。按prompt等权，固定共同队列与全体缺失分母，不能按质量筛出好看的速度子集。

## 尚缺什么

- 本轮GPU执行授权，以及批准时绑定具体host/UUID的整卡intent、中央预约、宿主监督/存储与独占准入。CPU stage不能直接作为GPU stage；本包没有签发或运行启动命令。
- 真正GPU数值等价和新T_DD/资源峰值只能在获准的A阶段验证；12条验证已经包含在73条与12GPUh中，失败即停，不再外加“试跑”。
- 若要GPU实测新方法价格而非当前工程报价，需要真实运行；本轮CPU不能给出该数字。最终16整卡报价仍独立，不妨碍本次有限CAL方案的审阅。

本包是可按明确阶段实施的整卡方案与生产请求组件，不声称新的宿主启动封装已做真实GPU验收。新批继续原门槛；DEV128/IG/CAL66/721/722原件和统计结论不改，PaperPort-UniPC不是Euler35精确复现，高速19D没有附加。
