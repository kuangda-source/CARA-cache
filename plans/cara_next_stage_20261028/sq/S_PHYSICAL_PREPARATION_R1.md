# S 复用入口与主机物理矩阵

2026-10-29。这是 S 采集的前瞻执行绑定与 CPU 组合准备，不是 GPU 授权或真实标签结果。原十条上限仍表示十个逻辑角色；实际新采样按主机和已核验旧 OFF 区分。

| 主机 | 新父路径 | 复用 OFF | 新 parent D/C | 额外 Dense/C | 实际 pair / heads |
|---|---:|---:|---:|---:|---:|
| A6000 | 9 | 1 | 195 / 129 | 56 / 52 | 432 / 864 |
| Ada | 10 | 0 | 220 / 140 | 56 / 52 | 468 / 936 |

两端仍有两次新入口 warm、四条 ON、108 行矩、八个 F19 raw 和 24 个去重锚点。旧 OFF 不产生独立样本，不提供 clean timing。A6000 复用是原 AV28 / Shared25-C / seed0，不能跨架构导入 Ada；原件或运行绑定不相容时在准入处停止，不能静默改矩阵。

[执行身份](S_EXECUTION_IDENTITY_R1.json)冻结两个原 FIT 请求、原模型配置与 WC 设置、checkpoint 身份、原生产数值源码、运行时及共享 eval 模式。AV28 请求逐字段与旧 DEV128 的原配置一致。辅助模型资产、实际 backend flags、源码/运行时/资源须在未来 GPU 准入时核验，当前没有完整 GPU 卡接受。

[新组合入口](../../../src/wcomr/sq_s_physical_r1.py)复用未改动的原完整采集器。它只对新角色调用原采样器/复位回调；旧 OFF 直接导入已接受的全 36 guided、最终 latent 与完整 MP4 解码 RGB 元数据，不创建新的采样目录。新视频先走相同的完整 MP4 解码摘要，编码前像素摘要单独保留；两条都是新轨迹时继续比较编码前像素，旧 OFF 没有该对象时不伪造摘要。108 标签与存储分母保持。

CPU 准备分别覆盖两端两种 flow：A6000 18 条新 tiny 路径 + 两份原 tiny OFF，Ada 20 条新 tiny 路径。每端九项控制、280 文件重读；另用一份 93 帧 / 432×768 纯黑合成 MP4，实际走生产适配器的默认解码路径并核对所有 RGB 字节。tiny sampler 的视频摘要仍明确标为 CPU stand-in，合成视频也不是 Cosmos 生成结果。

CPU 卡保持 2 CPU / 8 GiB / 1800 秒、GPU 隐藏、无网络、源与旧资产只读、仅独立 stage 可写。源码先发布，双端先恢复既有句柄；一旦存在原 stage 只恢复。真实 S GPU 生命周期、完整内存/存储边界及包括哈希/复制/I-O/释放的整卡报价仍待完成，Q1 的独立待授权状态保持。
