# S 独立终态、费用与产物字节验收 R3

本轮接通原句柄捕获、独立终态判定、唯一费用结算及释放后的完整文件字节检查。代码与本地 CPU 控制不构成 S GPU 批准或真实标签；没有查询计算服务器，没有 GPU 派发或真实中央账本写入。原 Q1 单卡批准与 S 优先次序保持。

## 终态与费用

`capture_cara_sq_s_r2.py` 必须绑定原 launch SHA。原 guardian、container CLI、supervisor、runner 全部退出、原容器关闭可证明后才取回完整结果；运行中只返回状态和尝试路径数，UNKNOWN 只恢复原件。

`sq_s_terminal_r2` 独立复核原登记源、双端物理范围、CPU proof、S 批准、完整报价、资产与输出合同、原中央预约、账单和释放字节。缺少完整 collection 的失败尝试仍可支付原账单；这不会接受技术结果。结算审计保留 226 GPUh 总限、其他作业和 16.5 GPUh 未知责任。

技术接受另外要求原 40 GiB/2 CPU/无 swap 容器成功退出、完整单次模型/矩阵数据、原独占控制和释放快照。该边界不改变原科学范围、阈值、输入、参数或失败分母。

## 长监控与文件字节

S 的 14–17 小时提案允许最多 512 MiB 连续监控。新检查器在原宿主逐行读取，保留原 SHA、样本数、45 秒间隔界、同一 runner、温度和输入绑定；不把整段监控塞进旧 Q1 的 16 MiB 抓取字段。一个实际超过 16 MiB 的本地日志已通过该路径；间隔、陈旧温度、外来 PID、90°C 和末尾缺失分别被拒绝。

文件检查器读取全部 108 份行 JSON、8 份 raw、24 份唯一 anchor、1 份 manifest 与 10 份视频，复核路径、大小、SHA、完整队列、源 anchor 身份、总字节及多余 partial。原采集器在 durable sink 返回后才添加的诊断耗时不在行文件内；验收器保留这一原行为，其余行字段严格比较。该检查不反序列化张量，也不增加 P1 hidden-head 或完整 pipeline replay 的接受。

`postprocess_cara_sq_s_r2.py` 要求 GPU 隐藏、原两 CPU affinity、8 GiB 地址空间与 3600 秒边界。它先审计原释放和中央结算，再消费独立 CPU 句柄、扫描原文件；输出仅表示完整数据和字节已接受，风险分析仍待后续。原矩阵、原件和账单不覆盖。

## 当前验证与剩余工作

本地组合 105 项：104 通过、1 项 Linux 子进程/lease 控制因本机环境跳过。新增验证包含实际小张量文件、完整 151 文件队列、字节损坏、缺失文件、额外 partial、重新绑定 checksum 后的行内容漂移、原生模块禁用 Torch 的导入，以及 CLI 的 GPU 隐藏拒绝。[本地 R3 回执](../../../reports/cara_sq_s_terminal_artifacts_local_r3_20261030.json)

所有 GPU/模型头信息、PID、容器、原生 CPU 批准和独占观测的终态测试都是显式 CPU 替身，不是真实 CUDA 或模型证据。完整生产入口仍未接受。现有 CPU 启动器会继承原已验 base 的完整 payload；静态读取的 overlay 文件列表不是完整登记，下一次 CPU 组合需核对实际继承后的源码与新文件。
