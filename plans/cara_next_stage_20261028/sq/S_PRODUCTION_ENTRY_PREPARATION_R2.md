# S 完整十角色入口的本地接通

本轮把已接受的 S 核心矩阵接到实际 Cosmos 模型入口、宿主分配、容器监督和中央整卡费用边界。完整生产 CPU 验收仍未完成；真实 S 标签为 0，没有 GPU 派发或真实中央账本写入。资源查询心跳继续暂停。

## 已实现的运行路径

`sq_s_stage_r2` 安装受 CPU 证明约束的独立源码，创建不可覆盖的 intent，并在启动宿主子进程前消费唯一交接。宿主子进程先发布自己的 PID/start ticks，再读取凭据；交接或观察结果不明时只恢复原件。

`cara_sq_s_guardian_r2` 复用原 `sq_gpu_allocation_r1` 和 S/Q 控制日志，持卡费用从模式准入开始，到原容器关闭和模式恢复结束。容器重查 RAM/CPU/磁盘也在该时钟内，拒绝仍保留失败账单。内部 supervisor 时钟仅供诊断，不重复计费。中央预约保持单一 RUN、226 GPUh 总限和旧 16.5 GPUh 未知责任，同机已有项目任务时拒绝另一张空卡。

容器使用单卡、2 CPU、40 GiB RAM/无 swap、`.9` CUDA 分配器上限、32 GiB 私有输出、28 GiB tensor 总限、2 GiB 单文件和独立 48 MiB 控制日志。输入、运行库和权重只读。连续监控保留完整历史；512 MiB 上限或热保护触发时先保存触发日志，再停止，不截断旧记录。

`run_cara_sq_s_r2` 在原独占上下文中调用已存在的单次模型加载和完整 S 矩阵入口。保持原两个 FIT 输入、seed0、93 帧、36 对求解、原采样/精度/WorldCache 参数。完成模型清理后重验完整数据与 typed witness，再保存结果。没有 CPU 替身可从实际 CLI 进入该路径。
