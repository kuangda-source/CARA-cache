# S 宿主内存准入修订

52 GiB不是实测最低需求，而是原40 GiB容器硬上限之外的12 GiB余量。原实际51.6689 GiB仍有11.6689 GiB余量，仅因0.3311 GiB差额阻断没有相应峰值证据支持。

准入改为50 GiB，即40 GiB硬上限加10 GiB宿主余量。容器仍禁止swap，GPU显存比例、存储与温度界、完整10路径/936heads/108行、原14 GPUh批准和失败即停均保持。尚未测得真实S物理峰值；本修订不把40 GiB称为实测用量。

保留原R2源包、52 GiB profile和全部回执；新的R4独立登记包只改准入/命名空间。所有数学、模型、采样与风险规则源码SHA保持。CPU证据复用原123项控制、20条tiny路径和五个Linux监督场景；另在两端执行新的32项受影响准入/生命周期控制，禁止Torch、模型加载和GPU。只有新组件验收并绑定新登记、资产和原存储后，才承接同一次S授权。不会用改过的源冒充原R2接受，也不重跑无关数学部分。

S仍须等待原Q1完整释放、唯一结算，并在实际提交时通过中央同主机责任、源/CPU/资产/盘/内存和硬件独占准入。不恢复空闲轮询。

原R3的第一次Linux CPU容器在测试前暴露了宿主/容器hostname不同的真实接线问题，失败包保留。R4用同一Linux内核boot ID绑定宿主与容器，并测试容器hostname变化和外来boot ID拒绝；原R2以及数学源码保持。

两端R4现已各32项Linux控制、零跳过并独立接受，原native123/20tiny/5监督证据按未改数学源码复用。新源3a85be21与原模型、数学、范围及14GPUh保持；实际执行绑定见 reports/cara_sq_s_RAM50_two_card_execution_authorization_r2_20261030.json。Q1全部GPU、释放、中央0.2987564935850807GPUh结算和全12状态CPU分析均已独立接受；q1-2/q1-3检查已删除，原q1空闲监控继续暂停。
